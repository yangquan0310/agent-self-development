# 设计哲学：从"代劳"到"赋能"

> **版本**：v2.0.0
> **日期**：2026-05-19
> **来源**：v4.3.0 架构决策（PM 杨权确认）

---

## 核心哲学

**一句话概括**：

> 插件不再告诉 Agent 该做什么，而是让 Agent 自己决定需要什么。

v4.3.0 的设计哲学可以用三个关键词概括：**拉取式**、**显式接口**、**被动响应**。

---

## 三个哲学转变

### 1. 从"推送式"到"拉取式"

| 维度 | v4.2.x | v4.3.0 |
|------|--------|--------|
| 控制权 | 插件**决定**注入什么 skill / 触发什么 Hook | Agent**选择**调用什么 tool |
| 通信模式 | 插件 → Agent（单向灌输） | Agent ↔ 插件（双向交互） |
| 隐喻 | 家长告诉孩子该做什么 | 图书馆让读者自己找书 |

**问题**：v4.2.x 插件假设"我比 Agent 更懂当前该做什么"，通过 Hook 注入 skill 文本。但插件没有 Agent 的完整对话上下文，注入的内容可能不是 Agent 当前最需要的。

**哲学**：Agent 拥有完整对话上下文，应该由 Agent 自主判断需要什么指导。插件只负责把能力摆出来，Agent 按需取用。

**代码体现**：
- v4.3.0 **完全移除** `before_prompt_build` 注入
- 无 Hook，无隐式行为
- Agent 自行读取 `SKILL.md` 或调用 `task.get()` 获取状态

---

### 2. 从"隐式契约"到"显式接口"

| 维度 | v4.2.x | v4.3.0 |
|------|--------|--------|
| 状态推进 | `[STATUS: active]` 标记（侧面通道，已废弃） | `task.update({ runId, status: "active" })` Tool（显式调用） |
| 任务创建 | `[NEED_PLAN]` 标记（已废弃） | `task.create({ prompt })` Tool（明确意图） |
| 信息传递 | 插件偷偷注入，Agent 可能感知不到 | Agent 主动调用，必然获得结果 |

**问题**：隐式标记容易丢失、格式不规范、Agent 不知道有哪些选择。

**哲学**：任何状态变更都应该有明确的接口和明确的调用者。Agent 调用 Tool 时，清楚知道自己在做什么、会触发什么。

**代码体现**：
- 8 个命名空间工具有明确的 parameters schema
- 输入/输出/错误处理全部可见
- 无标记、无 Hook 副作用

---

### 3. 从"插件代劳"到"Agent 自治 + 插件兜底"

| 维度 | v4.2.x | v4.3.0 |
|------|--------|--------|
| 插件文件操作 | 通过 Hook 主动操作 + Tool 被动响应 | **仅 Tool 被动响应** |
| 插件角色 | 工具层 + 隐式注入者 | **纯工具层** |
| Agent 选择 | 可以调用 Tool，也可以自己写文件 | 可以调用 Tool，也可以自己写文件 |

**哲学**：不让插件做决策（代劳），也不剥夺插件的能力。插件是"工具箱"，Agent 是"使用者"。Agent 有选择权：用工具方便，不用工具自由。

**代码体现**（扁平三层架构）：

```
┌─────────────────────────────────────────────────┐
│ Agent 层（自主决策）                              │
│ · 自行读取 SKILL.md、TODO.md                     │
│ · 按需调用 Tool                                  │
│ · 直接读写项目文件（可选）                        │
├─────────────────────────────────────────────────┤
│ Tool 层（8 个命名空间工具）                       │
│ task.create / task.update / task.advance         │
│ task.get / task.archive                          │
│ event.report / event.query / event.archive       │
│ → 纯函数 handler，无类、无状态、无 Hook           │
├─────────────────────────────────────────────────┤
│ 文件系统（项目级持久化）                          │
│ .agent/tasks/{runId}.json                        │
│ .agent/events/{date}/{runId}.md                  │
│ .agent/tasks/archive/ + .agent/events/archive/   │
└─────────────────────────────────────────────────┘
```

## 与 OpenClaw 生态的对齐

飞书官方插件的设计哲学：

> **"插件暴露能力，Agent 自主决策"**

v4.3.0 向这个哲学完全对齐：

```
飞书插件：api.registerTool() → Agent 列出可用 tools → 自主选择
v4.3.0：   api.registerTool() → Agent 列出可用 tools → 自主选择
```

不再做生态中的异类。v4.3.0 彻底移除了 Hook 注入，成为纯粹的 Tool Plugin。

---

## 哲学在代码中的体现

| 哲学原则 | 代码表现 |
|----------|----------|
| 拉取式 | **无注入**。Agent 自行读取 SKILL.md 或调用 task.get() |
| 显式接口 | 8 个命名空间工具有明确的 parameters schema |
| 被动响应 | `task.create()` 只在 Agent 调用时创建 task，插件不主动操作 |
| Agent 自治 | Agent 可直接写 `.agent/tasks/{runId}.json`，不强制走 Tool |
| 扁平简单 | 无类、无依赖注入、无 Hook 链，三层清晰 |

## 理论基础的支撑

设计哲学并非凭空产生，而是由理论基础支撑：

| 设计哲学 | 理论基础 |
|----------|----------|
| Agent 自治 | **工作自我理论**：工作自我是执行控制系统，Agent 应该自主调控 |
| 拉取式获取指导 | **自传体记忆**：以"我"为索引，Agent 自主决定需要什么经验 |
| 显式接口 | **分布式记忆**：外部辅助记忆需要明确的交互协议 |
| 被动响应 | **同化与顺应**：变化应由 Agent 自身驱动，而非外部强加 |

详见：`docs/reference/theory.md`

---

## 一句话总结

> **v4.3.0 的设计哲学是：把选择权还给 Agent。插件做"能力的提供者"，不做"决策的替代者"。**
>
> 从四层到三层，从类到函数，从 Hook 到纯 Tool —— 一切为了更简单、更透明、更可预测。
