# 设计哲学：从"代劳"到"赋能"

> **版本**：v1.0.0
> **日期**：2026-05-11
> **来源**：v4.1.0 架构决策（PM 杨权确认）

---

## 核心哲学

**一句话概括**：

> 插件不再告诉 Agent 该做什么，而是让 Agent 自己决定需要什么。

v4.1.0 的设计哲学可以用三个关键词概括：**拉取式**、**显式接口**、**被动响应**。

---

## 三个哲学转变

### 1. 从"推送式"到"拉取式"

| 维度 | v4.0.0 | v4.1.0 |
|------|--------|--------|
| 控制权 | 插件**决定**注入什么 skill | Agent**选择**调用什么 tool |
| 通信模式 | 插件 → Agent（单向灌输） | Agent ↔ 插件（双向交互） |
| 隐喻 | 家长告诉孩子该做什么 | 图书馆让读者自己找书 |

**问题**：v4.0.0 插件假设"我比 Agent 更懂当前该做什么"，但插件没有 Agent 的完整对话上下文，注入的 skill 可能不是 Agent 当前最需要的。

**哲学**：Agent 拥有完整对话上下文，应该由 Agent 自主判断需要什么指导。插件只负责把能力摆出来，Agent 按需取用。

**代码体现**：
- `before_prompt_build` 不再注入完整 skill 文本
- 只输出 1-2 句最小化提示：当前状态 + 可用 tools 列表
- Agent 调用 `get_planning_guide("assessment")` 获取指导

---

### 2. 从"隐式契约"到"显式接口"

| 维度 | v4.0.0 | v4.1.0 |
|------|--------|--------|
| 状态推进 | `[STATUS: active]` 标记（侧面通道） | `update_task_status(runId, "active")` Tool（显式调用） |
| 任务创建 | `[NEED_PLAN]` 标记（容易被忽略） | `create_plan()` Tool（明确意图） |
| 信息传递 | 插件偷偷注入，Agent 可能感知不到 | Agent 主动调用，必然获得结果 |

**问题**：隐式标记容易丢失、格式不规范、Agent 不知道有哪些选择。

**哲学**：任何状态变更都应该有明确的接口和明确的调用者。Agent 调用 Tool 时，清楚知道自己在做什么、会触发什么。

**代码体现**：
- 13 个 tools 有明确的 JSON Schema
- 输入/输出/错误处理全部可见
- `[STATUS]`/`[NEED_PLAN]` 保留但标记 deprecated

---

### 3. 从"插件代劳"到"Agent 自治 + 插件兜底"

| 维度 | v4.0.1 设想（已放弃） | v4.1.0 方案 C |
|------|----------------------|---------------|
| 插件文件操作 | 完全删除，Agent 全权 | 保留但改为**被动响应** |
| 插件角色 | 旁观者（只注入 + 日志） | 工具层（Agent 调用时才动作） |
| Agent 选择 | 只能自己写文件 | 可以调用 Tool，也可以自己写文件 |

**哲学**：不让插件做决策（代劳），但也不剥夺插件的能力（完全删除）。插件是"工具箱"，Agent 是"使用者"。Agent 有选择权：用工具方便，不用工具自由。

**代码体现**（方案 C 三层架构）：

```
┌─────────────────────────────────────────────────┐
│ 第一层：查询型 Tool（插件实现，只读）             │
│ get_task_status、get_planning_guide、self_diagnose│
│ → 插件读取 .agent/ 目录，返回结构化数据           │
├─────────────────────────────────────────────────┤
│ 第二层：操作型 Tool（插件实现，读写）             │
│ create_plan、update_task_status、record_deviation │
│ → 插件响应 Agent 显式调用，执行文件写入             │
│ → 关键：不是插件主动检测标记后自动操作              │
├─────────────────────────────────────────────────┤
│ 第三层：Agent 自主执行                            │
│ Agent 直接读写 .agent/ 文件系统                   │
│ （保留 v4.0.1 设想的自治权）                     │
└─────────────────────────────────────────────────┘
```

## 与 OpenClaw 生态的对齐

飞书官方插件的设计哲学：

> **"插件暴露能力，Agent 自主决策"**

v4.1.0 向这个哲学对齐：

```
飞书插件：api.registerTool() → Agent 列出可用 tools → 自主选择
v4.1.0：   api.registerTool() → Agent 列出可用 tools → 自主选择
```

不再做生态中的异类。

## 哲学在代码中的体现

| 哲学原则 | 代码表现 |
|----------|----------|
| 拉取式 | `before_prompt_build` 只输出 tools 列表，不再注入完整 skill |
| 显式接口 | 13 个 tools 有明确的 JSON Schema，输入/输出/错误处理可见 |
| 被动响应 | `create_plan()` 只在 Agent 调用时创建 task，插件不主动检测标记 |
| Agent 自治 | Agent 可直接写 `.agent/tasks/{runId}.json`，不强制走 Tool |

## 理论基础的支撑

设计哲学并非凭空产生，而是由理论基础支撑：

| 设计哲学 | 理论基础 |
|----------|----------|
| Agent 自治 | **工作自我理论**：工作自我是执行控制系统，Agent 应该自主调控 |
| 拉取式获取指导 | **自传体记忆**：以"我"为索引，Agent 自主决定需要什么经验 |
| 显式接口 | **分布式记忆**：外部辅助记忆需要明确的交互协议 |
| 被动响应 | **同化与顺应**：变化应由 Agent 自身驱动，而非外部强加 |

详见：`docs/reference/theory.md`

---

## 一句话总结

> **v4.1.0 的设计哲学是：把选择权还给 Agent。插件做"能力的提供者"，不做"决策的替代者"。**
