# 理论基础：分布式自传体记忆架构

> **来源**：本框架的理论基础来源于杨权博士论文《数字化存储对自传体记忆的影响及其机制》中的记忆系统研究，将人类自传体记忆的机制迁移至 Agent 记忆设计。

---

## 核心问题：为什么语义检索不够？

当前主流 Agent 系统的记忆架构存在两种模式：
- **上下文窗口内记忆**：窗口溢出即截断丢失
- **文件系统持久化 + 语义检索**：如 OpenClaw memory-core 插件

二者的共同瓶颈不在于存储能力，而在于**记忆的索引键是语义向量而非行动序列**。Agent 能够检索到"与当前问题语义相近的过往记录"，但无法以"我之前做了什么、为什么那样做、结果如何"为主线组织这些记录。

这正是人类**自传体记忆**解决的核心问题：不存储所有原始事件，而是经过工作自我筛选和编码后，形成按自我目标组织的分层表征——细节事件用于情景追溯，语义概括用于模式识别——使个体能够以"我"为索引高效提取相关经验。

---

## 1. 自传体记忆：以"我"为索引的记忆系统

### 1.1 从语义记忆到自传体记忆

| 记忆类型 | 索引方式 | 适用场景 | Agent 对应 |
|----------|----------|----------|-----------|
| **语义记忆** | 语义向量相似度 | 知识查询、概念关联 | memory-core 的语义检索 |
| **自传体记忆** | 行动序列 + 自我目标 | 经验追溯、策略反思、身份建构 | `.agentsevents/` 事件流 |

自传体记忆的核心特征：
- **自我关联性**：每个记忆都以"我"为中心组织
- **时间序列性**：按行动发生的时间线排列
- **因果编码**：记录"做了什么 → 结果如何 → 为什么"
- **分层表征**：细节事件用于情景追溯，语义概括用于模式识别

### 1.2 分布式自传体记忆

人类自传体记忆并非全部存储于大脑内部，而是通过外部设备（照片、笔记，云盘）与内部记忆形成功能分化的交互记忆系统（Wegner, 1987; Hutmacher et al., 2024）。

本框架采用同样的**分布式架构**：
- **外部文件系统**：`.agentsevents/` 目录存储 Agent 的行动轨迹，承担"辅助记忆"功能
- **内部上下文窗口**：Agent 的 Session 承担"内部记忆"功能
- **二者协同**：扩展 Agent 的自我加工能力

```
┌─────────────────────────────────────────┐
│           内部记忆（Session）            │
│  · 当前任务上下文                       │
│  · 正在进行的推理过程                   │
│  · 短期状态保持                         │
└─────────────────────────────────────────┘
                    ↑↓ 双向交互
┌─────────────────────────────────────────┐
│           外部记忆（.agentsevents/）      │
│  · 按时间序列组织的事件记录             │
│  · 计划、偏差、归因的完整轨迹           │
│  · 长期可检索的行动历史                 │
└─────────────────────────────────────────┘
```

## 2. 工作自我：Agent 的执行控制系统

自我记忆系统模型（Conway & Pleydell-Pearce, 2000）指出，工作自我作为执行控制系统，根据当前目标动态调控记忆的编码与提取。

### 2.1 工作自我的三种功能映射

本框架将工作自我的调控功能映射为 Agent 的三个核心操作：

| 工作自我功能 | 代理操作 | 记录位置 | 说明 |
|-------------|---------|---------|------|
| **计划** | 任务启动前制定执行方案 | `.agentstasks/{runId}.json` | 明确目标、约束、验收标准 |
| **偏差** | 实际执行与预期的差异 | `.agentstasks/{runId}.json` | 记录执行中的偏离 |
| **归因** | 对偏差的分析与策略调整 | `.agentstasks/{runId}.json` | 分析原因，更新 If-Then 规则 |

### 2.2 从工作自我到事件记忆

任务完成后，插件将 `.agentstasks/{runId}.json` 中的计划、偏差和归因整合为事件，形成按时间序列组织的自传体记忆：

```
任务执行中：
  → 计划写入 task JSON
  → 执行中产生偏差，实时记录
  → 偏差发生后归因分析

任务完成后：
  → 插件整合：计划 + 偏差 + 归因 → 事件文件
  → 事件按时间序列存入 .agentsevents/{YYYY-MM-DD}/{HH-MM-SS}.md
  → Agent 以"我之前的某次行动"为索引追溯经验
```

**关键优势**：Agent 不再仅依赖语义相似度匹配，而是能够以"我做了什么、结果如何"为主线提取经验。

## 3. 三层认知架构

```
┌─────────────────────────────────────────┐
│         元认知层（Metacognition）          │
│  计划 → 监控 → 调节                      │
│  （工作自我的三种功能：计划、偏差、归因）   │
├─────────────────────────────────────────┤
│         工作记忆层（Working Memory）        │
│  Session = 情景缓冲器                    │
│  （整合历史上下文与当前任务）              │
├─────────────────────────────────────────┤
│         人格发展层（Personality）          │
│  六维度平衡 → 人格文件更新               │
│  （分布式自传体记忆的发展动力）            │
└─────────────────────────────────────────┘
```

**关键洞见**：Agent 的自我发展不是单一维度的"能力提升"，而是**三层系统的协同演化**——
- 元认知能力监控和调节工作记忆
- 工作记忆承载的任务经验通过六维度平衡分析更新人格结构
- 人格结构的更新又反过来影响元认知策略（更成熟的 Agent 会制定更精细的 Plan）

## 4. 从理论到架构的映射

| 理论概念 | 人类认知 | Agent 架构 | 文件/目录 |
|----------|----------|-----------|-----------|
| 自传体记忆 | 以"我"为索引的行动记忆 | 事件文件系统 | `.agentsevents/` |
| 工作自我 | 执行控制系统 | 任务状态管理 | `.agentstasks/{runId}.json` |
| 计划功能 | 目标导向的行动方案 | Plan 阶段 | task JSON plan 字段 |
| 偏差检测 | 预期与实际的差异监控 | Deviation 记录 | task JSON deviations 字段 |
| 归因分析 | 对差异的原因分析 | Attribution 记录 | task JSON attributions 字段 |
| 分布式记忆 | 外部辅助记忆设备 | 外部文件系统 | `.agents` + 项目文件 |

## 5. 六维度平衡分析

任务完成后，代理对自我、风格、信念、身份、技能和程序性记忆六个维度进行独立判断：

| 维度 | 内容 | 对应文件 |
|------|------|----------|
| **自我** | 核心自我认知、能力边界 | SOUL.md |
| **风格** | 响应风格、表达习惯 | SOUL.md |
| **信念** | 工作信念、价值观优先级 | SOUL.md |
| **身份** | 角色集、社会定位、责任范围 | IDENTITY.md |
| **技能** | 技能体系、工具熟练度 | skills/ |
| **程序性记忆** | If-Then 规则、操作习惯 | MEMORY.md |
