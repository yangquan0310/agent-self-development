## 一、设计目标

将插件从「平面 Tool 集合」升级为「对象驱动的命名空间架构」：

1. **对象即边界**：TaskObject 是 `task.json` 的唯一写入者，EventObject 是 `event.md` 的唯一写入者，根治 RISK-4（多模块同构数据竞态）。
2. **命名空间即语义**：`task.*` 管理任务状态机，`event.*` 管理事件流，`guide.*` 提供认知指导。
3. **模板即契约**：`assets/task.json` 与 `assets/event.md` 作为 canonical 模板，是对象与文件系统之间的契约层。
4. **注册方式现代化**：全面适配 OpenClaw 新工具注册方式 `api.registerTool({ name, description, parameters, execute })`。

### 2.2 模块职责矩阵

| 模块 | 职责 | 不做什么 | 对应目录 |
|------|------|----------|----------|
| **TaskObject** | task.json 的完整生命周期：创建、读取、更新、推进、归档、诊断、校验 | 不直接操作文件系统（通过 State adapter） | `src/objects/task-object.js` |
| **EventObject** | event.md 的完整生命周期：创建、追加记录、查询、归档 | 不操作 task.json | `src/objects/event-object.js` |
| **State Adapter** | 纯 JSON 文件的原始读写：readJson / writeJson / listJson / deleteJson / exists | 不写业务逻辑（不维护 `updatedAt`、不校验 schema、不清理归档） | `src/common/adapters/state.js` |
| **Tool Registry** | 注册命名空间 tools、分发调用、包裹返回值格式 | 不实现业务逻辑 | `src/tools/index.js` |
| **Namespace Tools** | 接收 Agent 调用参数，委托给 Object 层，返回标准格式 | 不直接读写 adapters | `src/tools/namespaced/*.js` |
| **Assets** | 提供 canonical 模板和 schema，作为「契约」 | 不包含代码逻辑 | `assets/task.json`, `assets/event.md` |

## 三、关键架构决策（ADR-009 等）

### 决策 1：State Adapter 降级为纯 IO ✅

**决策**：State adapter 从「业务逻辑持有者」降级为「纯 IO 层」。

**现状问题**：
- State 当前维护 `archiveTask()`（含清理逻辑）、`saveTask()`（含 API fallback）、`_cleanupOldArchives()`
- 这些业务逻辑与 RISK-4（双重状态更新路径）直接相关
- 多个模块通过 State 隐式共享同一套 JSON 文件，形成「隐式共享内存」

**新边界**：

| 方法 | 旧职责（v4.2.0） | 新职责（v4.3.0） |
|------|-----------------|-----------------|
| `State.saveTask()` | 写 JSON + API fallback + 目录创建 | 仅原子写 JSON |
| `State.getTask()` | 读 JSON + API fallback | 仅读 JSON |
| `State.archiveTask()` | 移动文件 + 清理旧归档 + 校验状态 | **移除**，由 TaskObject 接管 |
| `State.listTasks()` | 列出 tasks 目录 | 保留（纯 IO） |
| `State.deleteTask()` | 删文件 + API fallback | 仅删文件 |

**新增原子方法**：
```javascript
class State {
  async readJson(path) → object | null
  async writeJson(path, data) → void        // 原子替换（temp → rename）
  async writeJsonAtomic(path, data) → void   // 显式原子写
  async listJson(dirPath) → object[]         // 读目录下所有 JSON
  async deleteJson(path) → void
  async exists(path) → boolean
}
```

**决策依据**：单一职责原则。IO 层只负责持久化，业务规则由 Object 层负责。消除「谁都可以写 State」的竞态风险。

**可逆性**：可逆。若发现性能瓶颈，可将部分缓存逻辑回迁至 State。

### 决策 2：TaskObject 与现有 Plan 类的关系 → 合并替代

**决策**：TaskObject 吸收 Plan 类的核心职责，Plan 类在 v4.3.0 中保留为「薄包装」（委托模式），v4.4.0 移除。

**现状对比**：

| 方法 | Plan (v4.2.0) | TaskObject (v4.3.0) |
|------|---------------|---------------------|
| 创建计划 | `Plan.createPlan()` → 写 State | `TaskObject.create()` → 校验 + 写 State |
| 确认计划 | `Plan.approvePlan()` → 改 status | `TaskObject.update()` → 改 status + 校验 |
| 完成阶段 | `Plan.completePhase()` → 推进 phase | `TaskObject.advance()` → 推进 + 自动完成检测 |

**Plan 类现状问题**：
- `Plan` 仅 3 个方法，且与 Tool Handler 中的 `create_plan` / `advance_phase` 逻辑重复
- `Plan` 同时依赖 `State` 和 `Flow`，但 Flow 职责模糊（RISK-6）
- `Plan` 无独立存在的业务价值

**迁移路径**：
```
v4.3.0 M1: TaskObject 实现完成
v4.3.0 M2: Plan 类改为委托模式（所有方法转发给 TaskObject）
v4.3.0 M4: 测试验证 Plan 零独立逻辑
v4.4.0:     移除 Plan 类
```

**ADR**: 本决策写入 `docs/adr/ADR-009-object-adapter-boundary.md` 第三节。

### 决策 3：EventObject 与现有 Event 类的关系 → 职责拆分

**决策**：EventObject 接管项目级 `event.md` 的全部操作；现有 `Event` 类降级为「系统级 EventLog 归档器」。

**职责重新划分**：

| 领域 | v4.2.0 Event 类 | v4.3.0 EventObject | v4.3.0 Event 类（改名建议） |
|------|-----------------|-------------------|---------------------------|
| `.agent/events/*.md` 创建 | ❌ 无 | ✅ `createEvent()` | ❌ 无 |
| `.agent/events/*.md` 追加 | ❌ 无（Tool Handler 直接写） | ✅ `record()` | ❌ 无 |
| `.agent/events/*.md` 查询 | ❌ 无 | ✅ `query()` | ❌ 无 |
| 系统级 EventLog 归档 | ✅ `archiveTask()` | ❌ 无 | ✅ 保留（可改名 MemoryArchive） |
| 系统级 EventLog 查询 | ✅ `queryEventLog()` | ❌ 无 | ✅ 保留 |

**EventObject 核心设计**：
- 采用「章节切片」追加策略，不重新渲染全文件
- 使用正则匹配章节边界（`## 5. 偏差`、`## 6. 归因`），在边界处追加
- 单次追加 < 50ms（经验阈值）
- 首次创建时从 `assets/event.md` 模板渲染

**现有 Event 类迁移**：
```javascript
// v4.3.0 中 Event 类改为 MemoryArchive 类（可选）
class MemoryArchive {
  constructor(memory) { this.memory = memory; }
  async archiveToEventLog(date, eventLog) → { archived }
  async queryEventLog(date) → eventLog[]
}
```

### 决策 5：返回值格式 → 统一适配层

**决策**：所有命名空间 tools 统一返回 `{ content: [{ type: "text", text: JSON.stringify(result) }] }`，通过 `ReturnAdapter` 包裹实现，不与业务逻辑耦合。

**适配器设计**：

```javascript
// src/tools/return-adapter.js
export function adaptReturn(result, options = {}) {
  return {
    content: [{
      type: 'text',
      text: JSON.stringify(result, null, options.pretty ? 2 : undefined)
    }]
  };
}

export function adaptError(error, options = {}) {
  const payload = { error: error.message || String(error) };
  
  return {
    content: [{
      type: 'text',
      text: JSON.stringify(payload)
    }],
    isError: true
  };
}
```

**与业务逻辑隔离**：
- Tool Handler（业务层）继续返回 `{ task, success: true }` 或 `{ error: '...' }`
- Tool Registry（注册层）在 `execute()` 中统一调用 `adaptReturn()` / `adaptError()`
- 若 OpenClaw 核心未来变更返回格式，只需修改适配器一处

## 四、接口契约定义

### 4.1 TaskObject 接口契约

```typescript
interface TaskObject {
  // 依赖注入
  constructor(deps: {
    state: State;           // 纯 IO adapter
    logger?: Logger;
    log?: Log;
    caseIndex?: CaseIndex;
    taskSchema: object;     // assets/task.json 加载后的 schema
  });

  // 创建任务
  async create(params: {
    runId: string;
    prompt: string;
    taskType?: 'coding' | 'research' | 'documentation';
    planInput?: PlanInput;
  }): Promise<{ task: Task; similarCases?: Case[] }>;

  // 查询任务（系统级）
  async get(runId: string): Promise<{ task: Task | null }>;

  // 查询任务关联文件（项目级）
  async getFiles(runId: string): Promise<{ files: FileRef[]; count: number }>;

  // 更新任务状态
  async update(params: {
    runId: string;
    status: TaskStatus;
    reason?: string;
  }): Promise<{ task: Task; previousStatus: TaskStatus }>;

  // 推进阶段
  async advance(params: {
    runId: string;
    phaseId?: string;
  }): Promise<{ task: Task; previousPhase: number; nextPhase: number; isComplete: boolean }>;

  // 归档任务
  async archive(runId: string): Promise<{ archived: boolean; archivedAt?: string; error?: string }>;

  // 诊断任务
  async diagnose(runId?: string): Promise<{ diagnosis: Diagnosis }>;

  // 校验任务结构
  validate(task: Task): { valid: boolean; errors?: string[] };
}
```

**校验规则（由 TaskObject.validate 执行）**：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|----------|
| `runId` | string | ✅ | 非空，匹配 `[a-zA-Z0-9_-]+` |
| `status` | string | ✅ | 枚举值：`draft`, `pending_approval`, `active`, `revising`, `completed` |
| `createdAt` | number | ✅ | 正整数时间戳 |
| `updatedAt` | number | ✅ | ≥ `createdAt` |
| `plan` | object | ✅ | 必须包含 `prompt`, `context`, `workspace`, `execution` |
| `plan.execution.phases` | array | ✅ | 至少 1 个元素，每个元素必须有 `id`, `name`, `status` |
| `deviations` | array | — | 若存在，每个元素必须有 `id`, `type`, `description`, `timestamp` |
| `attributions` | array | — | 若存在，每个元素必须有 `id`, `rootCause`, `strategy`, `timestamp` |

**原子写保证**：
```javascript
async writeJsonAtomic(path, data) {
  const tmpPath = `${path}.tmp.${Date.now()}`;
  await fs.writeFile(tmpPath, JSON.stringify(data, null, 2));
  await fs.rename(tmpPath, path);  // POSIX 原子重命名
}
```

### 4.2 EventObject 接口契约

```typescript
interface EventObject {
  // 依赖注入
  constructor(deps: {
    logger?: Logger;
    eventTemplate: string;   // assets/event.md 加载后的模板
  });

  // 创建事件文件（首次渲染模板）
  async createEvent(params: {
    runId: string;
    task: Task;
  }): Promise<{ eventFilePath: string }>;

  // 记录偏差或归因
  async record(params: {
    runId: string;
    recordType: 'deviation' | 'attribution';
    data: DeviationData | AttributionData;
  }): Promise<{ recorded: boolean; eventFilePath?: string; error?: string }>;

  // 查询事件
  async query(filters: {
    runId?: string;
    date?: string;      // YYYY-MM-DD
    type?: 'deviation' | 'attribution';
  }): Promise<{ events: EventRecord[]; count: number }>;

  // 归档事件
  async archive(runId: string): Promise<{ archived: boolean }>;
}
```

**章节追加策略**：

```javascript
// 伪代码：不重新渲染全文件，只追加到章节边界
async _appendToSection(filePath, sectionMarker, entry) {
  const content = await fs.readFile(filePath, 'utf-8');
  const regex = new RegExp(`(## ${sectionMarker}[\\s\\S]*?)(?=## |$)`);
  const match = content.match(regex);
  if (!match) return false;
  
  const insertPos = match.index + match[0].length;
  const newContent = content.slice(0, insertPos) + '\n' + entry + content.slice(insertPos);
  await fs.writeFile(filePath, newContent);
  return true;
}
```

### 4.3 State Adapter 降级后接口

```typescript
interface State {
  constructor(options?: { dir?: string });

  // 核心 IO（新增/变更）
  async readJson(path: string): Promise<object | null>;
  async writeJson(path: string, data: object): Promise<void>;
  async writeJsonAtomic(path: string, data: object): Promise<void>;
  async listJson(dirPath: string): Promise<object[]>;
  async deleteJson(path: string): Promise<void>;
  async exists(path: string): Promise<boolean>;

  // 便捷路径（保留，但内部使用新方法）
  taskFile(runId: string): string;
  archiveFile(runId: string): string;
}
```

**移除的方法**：
- `saveTask(runId, task)` → 由调用方使用 `writeJsonAtomic(this.taskFile(runId), task)`
- `getTask(runId)` → 由调用方使用 `readJson(this.taskFile(runId))`
- `archiveTask(runId)` → 由 TaskObject 实现
- `deleteTask(runId)` → 由调用方使用 `deleteJson(this.taskFile(runId))`
- `listTasks()` → 由调用方使用 `listJson(join(this.dir, 'tasks'))`

**保留的方法**（Session 相关暂不改动，RISK-5 在 P2 处理）：
- `saveSession()`, `getSession()`, `deleteSession()`, `listSessions()`, `listSessionsByStatus()`

## 五、数据流设计

### 5.1 任务创建数据流

```
Agent 调用 task.create({ runId, prompt, taskType })
  │
  ▼
Tool Handler: src/tools/namespaced/task-tools.js
  │
  ▼
TaskObject.create()
  ├── 1. 加载 assets/task.json → 作为默认值模板
  ├── 2. 生成 Task 结构（prompt / context / workspace / execution）
  ├── 3. TaskObject.validate(task) → 校验必填字段
  ├── 4. State.writeJsonAtomic(state.taskFile(runId), task)
  ├── 5. 若 caseIndex 可用 → caseIndex.findSimilarCases(goal, 3)
  └── 6. 返回 { task, similarCases? }
  │
  ▼
ReturnAdapter.adaptReturn(result)
  │
  ▼
{ content: [{ type: "text", text: "{\"task\":...,\"similarCases\":...}" }] }
```

### 5.2 偏差记录数据流

```
Agent 调用 event.record({ runId, recordType: 'deviation', data: {...} })
  │
  ▼
Tool Handler: src/tools/namespaced/event-tools.js
  │
  ▼
EventObject.record()
  ├── 1. 读取 task → 确认存在
  ├── 2. 若 event.md 不存在 → EventObject.createEvent(runId, task)
  ├── 3. _appendToSection(filePath, '5. 偏差', markdownEntry)
  ├── 4. 同时更新系统级 task.deviations（保持 task.json 一致性）
  │      └── TaskObject.update() 追加 deviations 数组
  └── 5. 返回 { recorded: true, eventFilePath }
  │
  ▼
ReturnAdapter.adaptReturn(result)
  │
  ▼
{ content: [{ type: "text", text: "{\"recorded\":true,...}" }] }
```

### 5.3 归档后清理数据流

```
TaskObject.archive(runId) 完成
  │
  ▼
├── 1. 移动 task.json 到 archive/
├── 2. 清理旧归档（保留最近 N 个）
├── 3. 归档认知轨迹
├── 4. 写入案例索引
└── 5. 触发系统级归档（若 MemoryArchive 可用）
```

## 七、命名空间工具映射总表

### 7.1 task.* 命名空间（7 个工具）

| 工具名 | 类型 | 描述 | 关键参数 | 返回值核心字段 |
|--------|------|------|----------|---------------|
| `task.create` | 操作 | 创建 draft task | `runId`, `prompt`, `taskType?`, `planInput?` | `{ task, similarCases? }` |
| `task.update` | 操作 | 更新 task 状态 | `runId`, `status`, `reason?` | `{ task, previousStatus }` |
| `task.advance` | 操作 | 推进 task 阶段 | `runId`, `phaseId?` | `{ task, previousPhase, nextPhase, isComplete }` |
| `task.query` | 查询 | 查询 task 完整状态 | `runId` | `{ task }` |
| `task.files` | 查询 | 查询 task 关联文件 | `runId` | `{ files, count }` |
| `task.diagnose` | 查询 | 诊断任务/插件 | `runId?` | `{ diagnosis }` |
| `task.archive` | 操作 | 归档 completed task | `runId` | `{ archived, archivedAt }` |

### 7.2 event.* 命名空间（2 个工具）

| 工具名 | 类型 | 描述 | 关键参数 | 返回值核心字段 |

| `event.record` | 操作 | 记录偏差或归因 | `runId`, `recordType`, `data` | `{ recorded, eventFilePath }` |

## 九、风险与缓解

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 命名空间迁移影响全量测试 | 🔴 高 | P0-1/P0-2 接口冻结后再启动 M2；测试全部改为命名空间调用；旧测试基线废弃 |

## 十、附录

### 10.1 新旧插件注册方式对比

**v4.2.0（旧）**：
```javascript
api.registerTool('create_plan', {
  name: 'create_plan',
  description: '...',
  inputSchema: { type: 'object', properties: {...} },
  handler: async (params) => { ... }
});
```

**v4.3.0（新）**：
```javascript
api.registerTool({
  name: 'task.create',
  description: '...',
  parameters: { type: 'object', properties: {...} },
  execute: async (_id, params) => {
    const result = await taskObject.create(params);
    return adaptReturn(result);
  }
});
```

```json
{
  "$schema": "./task-schema.json",

  "status": "draft",

  "updatedAt": "{{timestamp}}",

    "prompt": "{{prompt}}",
```
