# ADR-004：明确 Tool Handler 为状态更新唯一写入者

> **状态**：建议中（需 Developer 评估可行性）  
> **日期**：2026-05-13  
> **决策优先级**：🟡 P1  
> **可逆性**：需谨慎（涉及数据流变更）

---

## 背景

当前 `State.task` 存在**两个写入路径**：

### 路径 A：Tool Handler（权威来源）

`src/tools/metacognition-tools.js` 中的操作型 tools：
- `create_plan()` → `state.saveTask(runId, task)`
- `update_task_status()` → `state.saveTask(runId, task)`
- `advance_phase()` → `state.saveTask(runId, task)`
- `record_deviation()` / `record_attribution()` → `state.saveTask(runId, task)`

### 路径 B：Hook 层解析（双重保险）

`src/metacognition/module.js:612` 的 `_parseToolCallResult()`：

```javascript
async onBeforeAgentFinalize(event, ctx) {
  const toolCalls = ctx.toolCalls || event.toolCalls || [];
  for (const toolCall of toolCalls) {
    await this._parseToolCallResult(toolCall, runId);  // ← 再次修改 state
  }
}
```

两个路径无同步契约，存在竞态条件。且 hook 层解析是对 tool handler 实现细节的反向依赖（强耦合）。

---

## 决策

**Tool Handler 为 State.task 的唯一写入者。Hook 层（`before_agent_finalize`）只读观察，禁止二次写入。**

---

## 方案

### Step 1：移除 `_parseToolCallResult` 中的写入逻辑

将 `_parseToolCallResult` 改造为**只读校验器**：

```javascript
async _parseToolCallResult(toolCall, runId) {
  if (!toolCall || !toolCall.name) return;
  
  const { name, result } = toolCall;
  const task = await this._getTask(runId);
  if (!task) return;
  
  // 只校验，不写入
  switch (name) {
    case 'update_task_status': {
      if (result?.success && result.status === task.status) {
        this.logger.debug(`[Meta] tool 状态已同步: ${result.status}`);
      } else {
        this.logger.warn(`[Meta] tool 状态不一致: expected=${task.status}, actual=${result?.status}`);
      }
      break;
    }
    // ... 其他 case 同理
  }
}
```

### Step 2：确保 Tool Handler 返回完整快照

Tool handler 的 `result` 中应包含操作后的完整 task 状态，供 hook 层校验：

```javascript
// update_task_status handler
return { 
  success: true, 
  runId, 
  status: task.status,  // 写入后的新状态
  taskSnapshot: {       // 可选：完整快照用于校验
    status: task.status,
    updatedAt: task.updatedAt,
    revisionReason: task.revisionReason
  }
};
```

### Step 3：修复 `previousStatus` 逻辑错误

`metacognition-tools.js:271`：

```javascript
// 当前（错误）：status 已修改后才赋值 previousStatus
return { success: true, runId, status, previousStatus: task.status };
//                                           ↑ 这里已经是新状态了
```

应改为：

```javascript
const previousStatus = task.status;  // 先保存旧状态
task.status = status;                // 再修改
// ...
return { success: true, runId, status, previousStatus };
```

---

## 影响

| 影响面 | 说明 |
|--------|------|
| 数据一致性 | 消除竞态，单一写入源 |
| 调试能力 | 保留校验日志，不一致时可告警 |
| 向后兼容 | `[STATUS]` 标记解析（deprecated）不受影响，因其写入的是同一 task 对象 |
| 风险 | 若 Tool Handler 漏写，hook 层不再补写，需确保 tool handler 覆盖全部状态变更 |
