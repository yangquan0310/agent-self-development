## 1. 版本定位

v4.5.0 是 **Hook 精细化版本**，在 v4.4.0 扁平化工具插件架构基础上，引入条件触发的 Hook 注入机制，解决全量注入带来的噪声和上下文污染问题。

**核心升级**：从「全量 Hook 注入」→「条件触发精准提醒」

## 3. Hook 机制详解

### 3.1 after_tool_call Hook

**触发时机**：Agent 每次工具调用返回后

**注册方式**：
```javascript
api.on('after_tool_call', async (event) => {
  const { shouldInject, idempotencyKey, prependContext } = evaluateAfterToolCall(event);
  if (shouldInject) {
    await enqueueInjection(api, logger, idempotencyKey, prependContext);
  }
}, { priority: 50 });
```

**条件过滤**：只监听 `task.create`、`task.update`、`event.report` 三个工具，其他工具直接跳过。

**条件判断结果**：

| 工具 | 成功条件 | idempotencyKey | 提醒类型 |
|------|----------|----------------|----------|
| `task.create` | 返回含 runId | `agent-self-development:task-created` | 计划制定 |
| `task.update` | 返回含 deviationRecorded=true | `agent-self-development:deviation-detected` | 偏差分析 |
| `event.report` | 返回含 eventFilePath | `agent-self-development:event-generated` | 六维度复盘 |

### 3.2 before_prompt_build Hook

**触发时机**：Agent 每次构建 prompt 前

**注册方式**：
```javascript
api.on('before_prompt_build', async (event) => {
  const { shouldInject, idempotencyKey, prependContext } = await evaluateBeforePromptBuild(context);
  if (shouldInject) {
    await enqueueInjection(api, logger, idempotencyKey, prependContext);
  }
}, { priority: 50 });
```

**条件判断**（异步）：
1. 扫描 `.agents/tasks/` 目录
2. 读取所有 `.json` 文件，检查 `status` 字段
3. 若存在 `active` / `draft` / `pending_approval` 状态的任务 → 不注入
4. 若目录为空或无 active 任务 → 注入创建任务提醒

### 3.3 注入函数

```javascript
async function enqueueInjection(api, logger, idempotencyKey, prependContext) {
  try {
    await api.enqueueNextTurnInjection({
      idempotencyKey,
      prependContext,
    });
    logInfo(logger, `[agent-self-development] Injection queued: ${idempotencyKey}`);
  } catch (err) {
    logInfo(logger, `[agent-self-development] Injection failed: ${err.message}`);
  }
}
```

**幂等保证**：依赖 OpenClaw 框架的 `idempotencyKey` 去重机制。相同 key 的重复注入自动忽略。

## 4. 条件判断模块

### 4.1 evaluateAfterToolCall(event)

输入：`after_tool_call` 的 event 对象

```
event = {
  toolName: string,           // 工具名
  params: object,             // 调用参数
  result: object              // 返回结果（content[{type, text}]）
}
```

处理流程：
1. 解析 `result.content[0].text` 为 JSON（尝试）
2. 判断 `isSuccess = parsedResult && !parsedResult.error`
3. 按工具名匹配条件（M1/M2/M3）
4. 返回 `{ shouldInject, idempotencyKey, prependContext }`

### 4.2 evaluateBeforePromptBuild(context)

输入：插件 context（包含 baseDir）

处理流程：
1. 异步读取 `context.baseDir/.agents/tasks/` 目录
2. 遍历 `.json` 文件，解析 status 字段
3. 存在 active 状态 → `{ shouldInject: false }`
4. 无 active 任务 → `{ shouldInject: true, idempotencyKey, prependContext }`

## 5. 提醒内容设计

### 5.1 提醒文本结构

每个提醒包含：
- **标题行**：用 emoji + 类型名标识（如 `【任务创建提醒】`）
- **客观描述**：说明当前检测到的状态
- **行动建议**：用编号列表提供 2-5 条具体行动
- **不包含**：通用认知框架、自我认知长文

### 5.2 4 个提醒文本

| 提醒 | 内容概要 |
|------|---------|
| `REMINDERS.taskCreated` | 制定计划 → 拆解 TODO → 执行监控 → 归因分析 → 事件记录 |
| `REMINDERS.deviationDetected` | 偏差分类 → 归因分析 → 影响评估 → 调整策略 |
| `REMINDERS.eventGenerated` | 六维度：自我认知、风格判断、信念验证、身份一致性、技能评估、程序性记忆 |
| `REMINDERS.noActiveTask` | 评估工作 → task.create → task.update → event.* |

## 6. 数据流

### 6.1 任务创建后注入（M1）

```
Agent 调用 task.create
  → tool handler 写 .agents/tasks/{runId}.json
  → after_tool_call 触发
  → evaluateAfterToolCall({ toolName: 'task.create', result })
  → shouldInject=true
  → enqueueNextTurnInjection(idempotencyKey, prependContext)
  → 下一轮 Agent 收到「制定计划」提醒
```

### 6.2 偏差记录后注入（M2）

```
Agent 调用 task.update({ deviation: {...} })
  → tool handler 写 deviations[] 到 task.json
  → after_tool_call 触发
  → evaluateAfterToolCall({ toolName: 'task.update', result })
  → result.deviationRecorded=true
  → shouldInject=true
  → 下一轮 Agent 收到「归因分析」提醒
```

### 6.3 无任务时注入（M4）

```
before_prompt_build 触发
  → evaluateBeforePromptBuild(context)
  → 扫描 .agents/tasks/ 无 active 任务
  → shouldInject=true
  → enqueueNextTurnInjection(idempotencyKey, prependContext)
  → 下一轮 Agent 收到「创建任务」提醒
```

## 7. 技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 条件判断内聚位置 | `hooks/condition.js` | 独立模块便于测试，与工具逻辑解耦 |
| 结果解析方式 | JSON.parse content[0].text | 兼容 OpenClaw 标准返回格式 |
| before_prompt_build 扫描方式 | 同步 readdir + readFile | 简单直接，避免 async 复杂性 |
| 幂等实现 | OpenClaw idempotencyKey | 框架层保证，无需自实现去重 |
| Hook 优先级 | priority: 50 | 在正常处理流程中适时插入 |

## 8. 测试策略

### 8.1 单元测试（condition.js）

- `evaluateAfterToolCall`: 用 mock event 测试 M1/M2/M3 条件分支
- `evaluateBeforePromptBuild`: 用 mock fs 目录结构测试有/无 active task 场景

### 8.2 集成测试

- 实际调用 task.create，检查 after_tool_call 是否触发注入
- 实际调用 task.update(deviation=true)，检查注入内容
- 清理所有 tasks 后，触发 before_prompt_build，检查注入

## 9. 已知限制

| 限制 | 影响 | 缓解方式 |
|------|------|----------|
| before_prompt_build 扫描整个 tasks 目录 | 大型场景性能下降 | 未来可缓存 active task 列表 |
| idempotencyKey 依赖 OpenClaw 框架 | 框架不支持时失效 | 已在 v4.5.0 环境内使用 |
| M4 仅检查 status 字段 | 不区分任务优先级 | 未来可增加 priority 字段 |
