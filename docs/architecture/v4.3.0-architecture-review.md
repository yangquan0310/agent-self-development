# v4.3.0 架构审核报告：Object-Driven Tool Plugin

> **类型**：架构审核（代码现状 → 目标架构差距分析）  
> **版本**：v4.3.0  
> **审核者**：Architect  
> **日期**：2026-05-19  
> **范围**：src/ 全量代码 + docs/roadmap/v4.3.0.md  
> **结论**：架构方向正确，但当前代码处于「新旧并存」的过渡态，存在 3 项严重差距需立即修正。

---

## 一、目标架构回顾

v4.3.0 的核心决策：从「全功能认知框架」退回到「极简工具插件」。

```
src/
├── index.js              # 入口：仅初始化对象 + 注册 7 个工具
├── objects/
│   ├── TaskObject.js     # task.json 全生命周期（项目级 .agent/tasks/）
│   ├── EventObject.js    # event.md 全生命周期（项目级 .agent/events/）
│   └── index.js
├── assets/
│   ├── task.json         # 契约模板 + schema 基准
│   ├── event.md          # 契约模板
│   └── templates/        # 认知指导模板（可选）
├── tools/
│   ├── index.js          # 注册入口（OpenClaw 新规范）
│   ├── task-tools.js     # task.* 命名空间（5 个）
│   ├── event-tools.js    # event.* 命名空间（2 个）
│   ├── schemas.js        # parameters schema
│   └── return-adapter.js # 返回值统一适配
└── utils/
    ├── path.js           # 路径解析（项目级 + 系统级）
    ├── file.js           # 原子文件 IO
    └── validate.js       # task 结构校验
```

**暴露工具（7 个）**：
- `task.create` / `task.update` / `task.advance` / `task.query` / `task.archive`
- `event.record` / `event.query`

**删除清单**：metacognition/、working-memory/、personality/、common/adapters/、heartbeat.js、skills.js、stream.js、template-engine.js、case-index.js、cognitive-trace.js。

## 二、审核结果：差距矩阵

| # | 差距项 | 严重等级 | 现状 | 目标 | 影响 |
|---|--------|----------|------|------|------|
| G1 | **项目级 vs 系统级路径错位** | 🔴 严重 | TaskObject 通过 `State` adapter 写入 `~/.agent/state/...` | TaskObject 直接写入 `./.agent/tasks/{runId}.json` | 任务文件不在项目目录，Agent 无法跨项目复用上下文 |
| G2 | **新旧代码并存** | 🔴 严重 | `index.js` 同时初始化旧框架 + 新对象层 | `index.js` 仅保留 TaskObject/EventObject + 工具注册 | 依赖混乱、启动开销、维护困难 |
| G3 | **工具注册方式未升级** | 🔴 严重 | 仍使用旧版 `api.registerTool(name, { inputSchema, handler })` | 新版 `api.registerTool({ name, description, parameters, execute })` | 不符合 OpenClaw 新插件规范 |
| G4 | **TaskObject 残留依赖** | 🟡 中等 | 依赖 cognitive-trace、caseIndex、state adapter、log | 仅依赖 `utils/path.js` + `utils/file.js` | 无法完成目录精简目标 |
| G5 | **event.md 凝练生成能力未实现** | 🟡 中等 | `EventObject` 只有章节追加逻辑 | `EventObject` 应实现「从 task.json 一次性凝练生成完整 event.md」的能力 | event.md 无法作为 task 完成的最终报告输出 |
| G6 | **方法命名不一致** | 🟠 低 | `deviate()` / `attribute()` | `recordDeviation()` / `recordAttribution()` | roadmap 与代码接口不匹配 |
| G7 | **assets 模板不一致** | 🟠 低 | `assets/event.md` 含 `---` 分隔线；`_defaultTemplate()` 不含 | 两者应一致 | 测试/校验困难 |

## 三、严重差距详解

### 🔴 G1：项目级 vs 系统级路径错位

**现状分析**：

```javascript
// src/objects/TaskObject.js
import { State } from '../common/adapters/state.js';  // 系统级 adapter

async create(params) {
  await this.state.saveTask(runId, task);  // → ~/.agent/state/agent-self-development/tasks/{runId}.json
}
```

**目标设计**（roadmap v4.3.0）：

```
task.create ──→ TaskObject.create() ──→ .agent/tasks/{runId}.json（项目级）
```

**问题**：v4.3.0 的设计哲学是「Agent 在项目目录中自主管理任务」，任务文件应位于**被管理项目的根目录**下的 `.agent/tasks/`，而非插件系统目录 `~/.agent/state/`。

**当前 State adapter 行为**：
- Task：`~/.agent/state/agent-self-development/tasks/{runId}.json`
- Session：`~/.agent/state/agent-self-development/sessions.json`
- Archive：`~/.agent/state/agent-self-development/archive/`

**修正方案**：

1. 移除 `State` adapter 依赖
2. TaskObject 直接通过 `utils/file.js` 读写 `./.agent/tasks/{runId}.json`
3. 归档路径改为 `./.agent/tasks/archive/{runId}.json`
4. 若需要系统级记忆归档，由 `event.query` 或独立 Memory tool 负责，不作为 TaskObject 核心职责

```javascript
// 目标：TaskObject 内部 IO（示意）
import { readJson, writeJson } from '../utils/file.js';
import { resolveTaskPath } from '../utils/path.js';

async create(params) {
  const taskPath = resolveTaskPath(this.projectRoot, runId);
  await writeJson(taskPath, task);  // 原子写入
}
```

### 🔴 G2：新旧代码并存

**现状**：`src/index.js` 仍然导入了 15+ 个即将删除的模块，并初始化了完整的旧框架：

```javascript
// 旧框架（应删除）
import { Metacognition } from './metacognition/module.js';
import { WorkingMemory } from './working-memory/module.js';
import { Personality } from './personality/module.js';
import { Heartbeat } from './common/heartbeat.js';
import { State } from './common/adapters/state.js';
// ... 等 15+ 个模块

metacognition.register();
workingMemory.register();
personality.register();
heartbeat.register();
```

**目标**：`src/index.js` 应精简为：

```javascript
import { TaskObject, EventObject } from './objects/index.js';
import { registerTools } from './tools/index.js';
import { resolveProjectRoot } from './utils/path.js';

export default {
  id: 'agent-self-development',
  version: '4.3.0',
  register(api) {
    const projectRoot = resolveProjectRoot(api);
    const taskObject = new TaskObject({ projectRoot, logger: api.logger });
    const eventObject = new EventObject({ projectRoot, logger: api.logger });
    registerTools(api, { taskObject, eventObject });
  }
};
```

**过渡期风险**：新旧框架并存期间，旧框架的 Hook 注入可能与新工具的 Agent 自主调用产生冲突（如旧 Hook 修改 prompt 与新 tool-driven 哲学矛盾）。

**修正方案**：M1 里程碑应优先完成目录清理，而非保留旧代码作为「兼容层」。v4.3.0 是破坏性版本，无需向后兼容旧框架。

---

### 🔴 G3：工具注册方式未升级

**现状**：`src/tools/index.js` 仍使用 v4.2.0 的注册方式：

```javascript
api.registerTool(toolName, {
  name: schema.name,
  description: schema.description,
  inputSchema: schema.inputSchema,   // ← 旧字段名
  handler: async (params) => { ... } // ← 旧签名
});
```

**OpenClaw 新规范要求**：

```javascript
api.registerTool({
  name: 'task.create',
  description: '...',
  parameters: { type: 'object', properties: { ... } },  // ← 新字段名
  execute: async (_id, params) => { ... }                // ← 新签名（含 _id）
});
```

**返回值格式**：`{ content: [{ type: 'text', text: JSON.stringify(result) }] }`

当前 `return-adapter.js` 已适配返回值格式，但注册方式和参数签名未更新。

**修正方案**：

1. `schemas.js`：`inputSchema` → `parameters`
2. `tools/index.js`：`api.registerTool(name, { ... })` → `api.registerTool({ name, ... })`
3. Tool Handler 签名：`async (params)` → `async (_id, params)`

## 四、中等差距详解

### 🟡 G4：TaskObject 残留依赖

当前 TaskObject 构造函数依赖：

| 依赖 | 应否保留 | 说明 |
|------|----------|------|
| `state` (State adapter) | ❌ 移除 | 替换为 `utils/file.js` 直接 IO |
| `logger` | ⚠️ 可选 | OpenClaw `api.logger` 可传入，但不应是强依赖 |
| `log` (Log adapter) | ❌ 移除 | 工具插件不应维护独立日志系统 |
| `caseIndex` | ❌ 移除 | 非核心职责，v4.3.0 废弃 |
| `events` (MemoryArchive) | ❌ 移除 | 系统级归档非核心职责 |
| `taskSchema` | ✅ 保留 | 作为校验基准 |
| `maxArchivedTasks` | ⚠️ 简化 | 保留但默认值即可，无需配置 |

**内部方法残留**：

- `diagnose()`：引用 `getTraceStats`、`getRecentTraces`（cognitive-trace）、`caseIndex.findSimilarCases`、`task.files` / `task.diagnose` 等已废弃工具名。该方法应**移除**或**大幅简化**（仅返回 task 基本状态）。
- `_buildTrendAnalysis()`：依赖认知轨迹和案例索引，应移除。
- `getFiles()`：功能上读取项目级 `.agent/tasks/{runId}.json`，但当前通过 `resolveTaskFilePath` 读取。若 task.json 改为项目级存储，该方法可保留但需调整路径。

**修正方案**：TaskObject 精简后仅保留：

```javascript
class TaskObject {
  constructor({ projectRoot, taskSchema, logger }) {
    this.projectRoot = projectRoot;
    this.taskSchema = taskSchema;
    this.logger = logger;
  }
  // 核心方法
  async create(params)
  async get(runId)
  async update(params)
  async advance(params)
  async archive(runId)
  // 新增方法（v4.3.0）
  async recordDeviation(runId, data)
  async recordAttribution(runId, data)
  async setOutcome(runId, data)
  async linkEventFile(runId, eventFilePath)
  // 校验
  validate(task)
}
```

### 🟡 G5：event.md 凝练生成能力未实现

**用户决策（2026-05-19）**：

> event.md 改为从 task.json 中凝练，**只有当 task 完成后，再写入 event.md**。

这意味着 event.md 不再是「实时追加的日志」，而是「task 完成后的最终报告」。

**影响分析**：

| 维度 | 原设计（实时追加） | 新设计（延迟凝练） |
|------|-------------------|-------------------|
| 偏差/归因存储 | task.json + event.md 双写 | **只写 task.json** |
| event.md 生成时机 | 每次 `event.record` 实时追加 | **task 完成时一次性生成** |
| EventObject 职责 | 章节切片追加 | **模板渲染引擎** |
| 一致性风险 | 双写可能不一致 | **单写源，零一致性问题** |
| 查询进行中偏差 | `event.query` 读 event.md | `task.query` 读 task.json 的 `deviations[]` |

**修正方案**：

1. **删除 EventObject 的章节追加逻辑**：`_appendToSection()`、`_defaultTemplate()` 中用于追加的注释锚点不再需要
2. **EventObject 新增 `render(task)` 方法**：接收完整的 task 对象，从 `assets/event.md` 模板渲染生成完整 Markdown
3. **`event.record` 工具**：只更新 task.json 的 deviations/attributions，不操作 event.md
4. **event.md 触发时机**：`task.archive()` 或 `task.advance()` 检测到 `isComplete = true` 时，调用 `EventObject.render(task)` 生成 event.md

```javascript
// EventObject.render(task) 示意
async render(task) {
  const template = await this._loadTemplate();  // 从 assets/event.md
  const vars = this._extractVarsFromTask(task); // 从 task.json 凝练数据
  const markdown = this._renderTemplate(template, vars);
  const eventPath = resolveEventPath(this.projectRoot, task);
  await writeFile(eventPath, markdown);
  return { eventFilePath: eventPath };
}
```

**关键决策**：TaskObject 是全生命周期中 deviations/attributions 的**唯一写入者**。EventObject 在 task 完成后只做一次性的「读取-渲染-写入」。对象间仍零耦合。

### 🟠 G7：assets 模板不一致

`assets/event.md` 与 `EventObject._defaultTemplate()` 的差异：

- `assets/event.md` 含 `---` 分隔线和注释说明
- `_defaultTemplate()` 不含 `---` 分隔线

**建议**：两者统一为 `assets/event.md` 的格式（含 `---` 分隔线，结构更清晰），删除 `_defaultTemplate()` 中的内联模板，改为始终从 `assets/event.md` 加载。

## 六、数据流健康度（目标态）

```
Agent 调用 task.create(params)
    ↓
Tool Handler (task-tools.js)
    ↓
TaskObject.create()
    ├── 校验参数
    ├── 生成 task 对象
    └── utils/file.js:writeJson('./.agent/tasks/{runId}.json', task)
    
Agent 调用 event.record({ runId, recordType: 'deviation', data })
    ↓
Tool Handler (event-tools.js)
    ├── TaskObject.recordDeviation(runId, data)
    │   └── 更新 './.agent/tasks/{runId}.json' 的 deviations[]
    └── EventObject.record({ runId, recordType, data, task })
        └── 追加 './.agent/events/{date}/{time}.md' 的偏差章节
```

**核心原则**：
1. **对象即边界**：TaskObject 只写 task.json，EventObject 只写 event.md
2. **Tool Handler 协调**：跨对象操作由 Tool Handler 编排，对象之间不直接调用
3. **项目级优先**：所有 Agent 可见的数据位于 `./.agent/`（项目级），系统级数据仅限插件内部使用（v4.3.0 中应无系统级数据）

## 七、架构决策建议

### ADR-010：项目级文件系统优先（v4.3.0）

| 维度 | 决策 |
|------|------|
| **背景** | v4.2.0 及之前使用系统级 `~/.agent/state/` 存储 task.json，Agent 无法跨项目复用任务上下文 |
| **决策** | v4.3.0 所有 Agent 可见的 task/event 数据均写入项目级 `./.agent/` |
| **影响** | State adapter / Memory adapter / Flow adapter 不再被 TaskObject/EventObject 使用；可完全移除 |
| **可逆性** | 不可逆（破坏性变更） |

### ADR-011：对象间零耦合

| 维度 | 决策 |
|------|------|
| **背景** | TaskObject 与 EventObject 在业务上有关联（偏差/归因同时影响 task.json 和 event.md） |
| **决策** | 对象之间不直接调用，跨对象操作由 Tool Handler 层编排 |
| **影响** | Tool Handler 承担协调者角色，对象保持单一职责 |
| **可逆性** | 可逆（未来可在对象层引入事件总线，但当前保持简单） |

### ADR-012：返回值统一适配

| 维度 | 决策 |
|------|------|
| **背景** | OpenClaw 新规范要求工具返回 `{ content: [{ type: 'text', text }] }` |
| **决策** | 所有 Tool Handler 返回原始 JS 对象，`tools/index.js` 统一通过 `return-adapter.js` 包装后注册 |
| **影响** | Handler 编写者无需关心返回格式，关注点分离 |
| **可逆性** | 可逆 |

## 八、M1 里程碑关键路径（修正版）

原 roadmap M1 目标：「目录清理 + utils 提取 + objects 精简」。

基于审核发现，M1 应按以下顺序执行：

```
Step 1: 新建 utils/ 骨架
  ├── utils/path.js     ← 从 project-context.js 迁移项目级路径函数
  ├── utils/file.js     ← 新建：原子 readJson / writeJson / ensureDir
  └── utils/validate.js ← 从 TaskObject.validate() 迁移

Step 2: 重写 TaskObject（去 adapter 化）
  - 移除 state / log / caseIndex / events / cognitive-trace 依赖
  - IO 改为 utils/file.js
  - 路径改为项目级 ./.agent/tasks/
  - 新增 recordDeviation / recordAttribution / setOutcome / linkEventFile
  - 删除 diagnose() 或大幅简化

Step 3: 重写 EventObject（延迟渲染模式）
  - 移除 project-context.js 依赖，改用 utils/path.js
  - 删除章节追加逻辑（`_appendToSection` 等），不再实时追加
  - 统一模板来源：始终从 assets/event.md 加载
  - 新增 `render(task)` 方法：从 task.json 凝练数据，一次性生成完整 event.md
  - event.md 生成时机：由 task.advance / task.archive 的 Tool Handler 在 isComplete 时触发

Step 4: 精简 index.js
  - 删除所有旧框架导入和初始化
  - 仅保留 TaskObject + EventObject + registerTools

Step 5: 删除旧目录
  - src/metacognition/、src/working-memory/、src/personality/
  - src/common/adapters/、src/common/heartbeat.js、src/common/skills.js
  - src/common/stream.js、src/common/template-engine.js
  - src/common/case-index.js、src/common/cognitive-trace.js
```
