# ADR-013：event.md 延迟凝练策略（v4.3.0）

> **状态**：已确认（PM 决策）  
> **日期**：2026-05-19  
> **决策优先级**：🟡 P1  
> **可逆性**：可逆（未来可恢复为实时追加，但当前不推荐）

---

## 背景

v4.2.0 及之前的 event.md 采用「实时追加」策略：每次记录偏差/归因时，直接追加到 event.md 的对应章节。

这种设计的弊端：
1. **双写风险**：task.json 的 `deviations[]` / `attributions[]` 与 event.md 的章节内容需保持同步，存在不一致风险
2. **追加逻辑复杂**：EventObject 需实现章节切片、正则匹配、锚点定位等 fragile 的文本操作
3. **内容不完整**：实时追加时，task 的最终 outcome、总阶段数、完成状态等信息尚未确定，event.md 作为「最终报告」是残缺的

---

## 决策

**event.md 改为「延迟凝练」策略：只在 task 完成后，从 task.json 一次性生成完整的 event.md。**

| 维度 | 实时追加（v4.2.0） | 延迟凝练（v4.3.0） |
|------|-------------------|-------------------|
| 偏差/归因存储 | task.json + event.md | **只写 task.json** |
| event.md 生成时机 | 每次 `event.record` | **task 完成时一次性生成** |
| EventObject 职责 | 章节切片追加引擎 | **模板渲染引擎** |
| 一致性风险 | 双写可能不一致 | **单写源，零风险** |
| 内容完整性 | 残缺（缺少 outcome） | **完整（含全部生命周期数据）** |
| 查询进行中偏差 | `event.query` 读 event.md | **`task.query` 读 task.json** |

---

## 方案

### 1. TaskObject：偏差/归因的唯一写入者

```javascript
// objects/TaskObject.js
async recordDeviation(runId, { type, description, impact }) {
  const task = await this.get(runId);
  task.deviations.push({ id: `dev-${Date.now()}`, type, description, impact, timestamp: Date.now(), attributed: false });
  await this._save(task);
}

async recordAttribution(runId, { rootCause, strategy, impact }) {
  const task = await this.get(runId);
  const attribution = { id: `attr-${Date.now()}`, rootCause, strategy, impact, timestamp: Date.now() };
  task.attributions.push(attribution);
  // 标记未归因偏差为已归因
  task.deviations.forEach(d => { if (!d.attributed) { d.attributed = true; d.attributionId = attribution.id; } });
  await this._save(task);
}
```

### 2. EventObject：task 完成后的最终渲染器

```javascript
// objects/EventObject.js
async render(task) {
  const template = await this._loadTemplate();      // 从 assets/event.md 加载
  const vars = this._extractFromTask(task);         // 从 task.json 凝练全部数据
  const markdown = this._renderTemplate(template, vars);
  const eventPath = resolveEventPath(this.projectRoot, task);
  await writeFile(eventPath, markdown);
  return { eventFilePath: eventPath };
}
```

### 3. `event.record` 工具语义（已确认）

`event.record` 职责：**task 完成后，从 task.json 凝练生成 event.md**。

```javascript
// tools/event-tools.js
async function event_record(params) {
  const { runId } = params;
  const task = await taskObject.getArchivedTask(runId);  // 从 archive/ 读取
  const result = await eventObject.generate(runId, task);
  return adaptReturn({ eventFilePath: result.eventFilePath });
}
```

> **关键决策**：event.md 是**独立产物**，不由 task 工具自动触发。Agent 显式调用 `event.record` 决定是否生成事件报告。

### 4. 偏差/归因的记录入口（已确认）

**偏差和归因是 task 的事情**，通过 `task.*` 工具记录到 task.json：

```javascript
// 方案：task.update 扩展参数
task.update({
  runId,
  status?,        // 可选
  reason?,        // 可选
  deviation?,     // 新增可选：{ type, description, impact }
  attribution?,   // 新增可选：{ rootCause, strategy, impact }
  outcome?,       // 新增可选：{ summary, deliverables, lessonsLearned }
  eventFilePath?  // 新增可选：关联 event.md 路径
});
```

> **说明**：`task.update` 扩展为「通用更新接口」，支持状态、偏差、归因、outcome 的任意组合更新。TaskObject 内部根据传入字段路由到 `update()` / `recordDeviation()` / `recordAttribution()` / `setOutcome()` / `linkEventFile()`。

---

## 影响

| 影响面 | 说明 |
|--------|------|
| 数据一致性 | 单写源设计，彻底消除 task.json 与 event.md 的不一致风险 |
| EventObject 复杂度 | 删除 `_appendToSection`、章节锚点匹配等 fragile 逻辑，实现大幅简化 |
| event.md 质量 | 作为「最终报告」而非「实时日志」，内容完整、结构统一 |
| 查询能力 | 进行中的任务偏差通过 `task.query` 获取；已完成的任务事件通过 `event.query` 获取 event.md |
| 调试 | 若 task 进行中崩溃，event.md 不存在，但 task.json 始终完整，数据零丢失 |

---

## 边界约定

| 阶段 | task.json | event.md | Agent 查询方式 |
|------|-----------|----------|---------------|
| draft / active / revising | 实时更新，含 deviations/attributions | **不存在** | `task.query` 获取偏差/归因 |
| completed + archived | 归档到 `./.agent/tasks/archive/` | **Agent 显式调用 `event.record` 生成** | `event.query` 获取最终报告 |
