# v4.1.0 Roadmap: Tool-Driven Agent Autonomy

> **核心目标**：从 "Hook 注入 Skill" 架构迁移到 "Tool 暴露 + Agent 自主调用" 架构，与 OpenClaw 飞书官方插件的设计模式对齐。
> **状态**：draft
> **创建时间**：2026-05-09
> **预计完成**：2026-05-15

---

## 1. 问题诊断

### 问题 1：当前架构是"推送式"，Agent 没有选择权

**现状**：插件通过 `before_prompt_build` 根据 `task.status` 决定注入什么 skill。Agent 被动接收，无法主动查看其他阶段的指导。
**根因**：设计假设"插件比 Agent 更懂当前该做什么"，但实际上 Agent 应该自主判断阶段。
**影响**：
- Agent 一旦进入 active 阶段，就看不到 planning 阶段的指导
- Agent 无法在执行中随时回顾 regulation 或 monitoring 的完整指导
- 每轮对话都注入大量 skill 文本，system context 膨胀

### 问题 2：与 OpenClaw 生态主流设计脱节

**现状**：飞书官方插件、天气插件等 OpenClaw 生态的主流插件都采用 `api.registerTool()` 暴露能力，Agent 主动调用。本插件却完全依赖 Hooks 注入。
**根因**：v1-v3 时代 OpenClaw 的 Tool API 不成熟， Hooks 是主要扩展方式。v2026.3+ Tool API 已成熟。
**影响**：
- Agent 对本插件的能力没有直观认知（不像飞书插件，Agent 可以列出所有可用 tools）
- 插件能力无法被 Agent 的 tool planning 机制利用
- 与 OpenClaw 最佳实践不一致

### 问题 3：状态切换依赖隐式标记

**现状**：Agent 输出 `[STATUS: xxx]` 或 `[NEED_PLAN]` 标记，`before_agent_finalize` 解析后更新状态。这是"侧面通道"通信，不直观。
**根因**：没有提供显式的 tool 让 Agent 调用以推进状态。
**影响**：
- Agent 可能忘记输出标记，导致状态不更新
- 标记解析容易出错（格式不规范）
- Agent 对状态变更有多少种选择不清楚

## 2. 飞书官方插件的设计参考

| 设计模式 | 飞书官方插件 | 当前本插件 | v4.1.0 目标 |
|----------|-------------|-----------|------------|
| 能力暴露 | `api.registerTool()` 暴露工具 | `api.on('before_prompt_build')` 注入文本 | **Tool 暴露为主，最小化注入为辅** |
| Agent 认知 | Agent 列出可用 tools，自主选择 | Agent 看不到有哪些 skill 可用 | **Agent 可见所有可用 tools** |
| 资源发现 | `feishu-office` 先 discovery 再操作 | 插件直接注入文件列表 | **Agent 调用 tool 获取上下文** |
| 状态诊断 | `feishu-auth-doctor` 自我诊断 | 无诊断工具 | **提供 `self_diagnose` tool** |
| 通信方式 | Tool 调用（显式） | `[STATUS]` 标记（隐式） | **Tool 调用替代标记** |

**核心洞见**：飞书插件的设计哲学是 **"插件暴露能力，Agent 自主决策"**。本插件当前是 **"插件替 Agent 决策，Agent 被动执行"**。

## 3. 解决方法与决策

### 方案：Tool 暴露 + 最小化 Hook 注入（混合过渡）

**架构变革**：
```
v4.0.0（当前）                    v4.1.0（目标）
┌─────────────────┐              ┌─────────────────┐
│ 插件决定注入什么 │              │ 插件暴露 Tools  │
│ Agent 被动接收   │      →      │ Agent 主动调用  │
└─────────────────┘              └─────────────────┘
```

### 3.1 新增 Tools（核心）

通过 `api.registerTool()` 注册以下 tools：

| Tool | 输入 | 输出 | 职责 | 对应原功能 |
|------|------|------|------|-----------|
| `get_planning_guide` | `phase: "assessment" \| "draft" \| "pending_approval" \| "revising"` | `guide: string` | 获取 planning 阶段指导 | 原 planning skill 注入 |
| `get_monitoring_guide` | `runId: string` | `guide: string + currentPhase + historyDeviations` | 获取 monitoring 指导 | 原 monitoring skill 注入 |
| `get_regulation_guide` | `runId: string` | `guide: string + deviationSummary` | 获取 regulation 指导 | 原 regulation 条件注入 |
| `get_development_guide` | `runId: string` | `guide: string + eventSummary` | 获取 development 指导 | 原 development skill 注入 |
| `get_task_status` | `runId: string` | `task: TaskJSON` | 查询当前 task 完整状态 | 原 State.getTask() |
| `get_task_files` | `runId: string` | `files: File[]` | 获取任务关联文件列表 | 原 `_getTaskFilePaths()` |
| `create_plan` | `planInput: { goal, constraints, successCriteria, phases }` | `task: TaskJSON` | 创建 Plan，返回 draft task | 原 `_createTask()` + `[NEED_PLAN]` |
| `update_task_status` | `runId, status, reason?` | `success: boolean` | 显式更新 task 状态 | 替代 `[STATUS: xxx]` 标记 |
| `advance_phase` | `runId, phaseId?` | `success: boolean + nextPhase` | 推进到下一阶段 | 原 `phase.status = completed` |
| `record_deviation` | `runId, type, description, impact` | `success: boolean` | 记录偏差到事件文件 | 原手动写入事件文件 |
| `record_attribution` | `runId, rootCause, impact, strategy` | `success: boolean` | 记录归因到事件文件 | 原手动写入事件文件 |
| `self_diagnose` | — | `diagnosis: { taskStatus, phase, deviations, toolsAvailable }` | 自我诊断当前任务状态 | 新增能力 |
| `archive_task` | `runId: string` | `success: boolean` | 归档任务 | 原 `agent_end` 归档 |

### 3.2 Hook 职责调整

| Hook | v4.0.0 职责 | v4.1.0 职责 |
|------|------------|------------|
| `before_prompt_build` | 根据 task.status 注入大量 skill 文本 | **仅注入最小化提示**：当前 task 状态摘要 + 可用 tools 列表（1-2 句） |
| `before_agent_finalize` | 解析 `[STATUS]`/`[NEED_PLAN]` 标记 | **解析 tool 调用结果** + 保留 `[STATUS]` 解析（向后兼容，标记 deprecated） |
| `after_tool_call` | 记录工具错误、审计文件变更 | 不变 |
| `agent_end` | 归档 task、清理资源 | 不变 |
| `llm_output` | 流式缓冲聚合 | 不变 |

### 3.3 Agent 行为变化

**v4.0.0 行为**：
```
用户输入 → 插件注入 skill → Agent 按 skill 指导执行 → 输出标记 → 插件解析标记更新状态
```

**v4.1.0 行为**：
```
用户输入 → Agent 调用 get_task_status() 了解状态
    ├─ 无 task → 调用 get_planning_guide("assessment") → 评估 → 调用 create_plan()
    ├─ draft → 调用 get_planning_guide("draft") → 制定 Plan → 调用 update_task_status("pending_approval")
    ├─ active → 调用 get_monitoring_guide() → 执行 → 调用 advance_phase() 或 record_deviation()
    ├─ revising → 调用 get_planning_guide("revising") → 修订 → 调用 update_task_status("active")
    └─ completed → 调用 get_development_guide() → 分析同化/顺应 → 调用 archive_task()
```

### 3.4 `before_prompt_build` 最小化注入模板

```
【Agent Self-Development 插件】

当前任务状态：{task.status}（runId: {runId}）
当前阶段：{currentPhase + 1}/{totalPhases}
可用工具：get_planning_guide, get_monitoring_guide, get_regulation_guide, 
         get_development_guide, get_task_status, create_plan, update_task_status, 
         advance_phase, record_deviation, record_attribution, self_diagnose, archive_task

你可以随时调用上述工具获取指导或推进任务。如需了解某个工具的用法，直接调用即可。
```

## 4. 兼容性评估

| 变更 | 兼容性 | 处理方案 |
|------|--------|---------|
| 新增 Tools | 向后兼容 | 新增功能，不影响现有流程 |
| `before_prompt_build` 注入简化 | **[BREAKING]** | 通过配置开关 `injectionMode: "legacy" \| "tool-driven"` 控制，默认 `"tool-driven"` |
| `[STATUS]`/`[NEED_PLAN]` 标记 | 向后兼容（deprecated） | `before_agent_finalize` 继续解析标记，但推荐改用 tool 调用 |
| Skill 文件（SKILL.md） | 向后兼容 | 保留作为 tool 返回的文本源，不删除 |
