# v4.0.0 Roadmap: Project Context Layer & Multi-Agent Collaboration

> **核心目标**：建立「项目上下文层」，使多 Agent 能在同一项目中协作。
> **状态**：active
> **创建时间**：2026-05-08
> **预计完成**：2026-05-15

---

## 1. 问题诊断

### 问题1：项目没有标准协作目录
现有项目接入 OpenClaw 时，Agent 不知道文件该放哪、怎么找其他 Agent 的成果。

### 问题2：缺少可执行的协作协议
没有定义 Agent 怎么举手、怎么汇报、插件什么时候督促。

### 问题3：插件 Hook 注入有问题
- regulation skill 从未注入（`src/metacognition/module.js` 实例化但未调用）
- monitoring 在 `before_prompt_build` 注入，但此时输出还没生成
- working-memory 标记 `reference_only`，Agent 看不到 Session 管理规则

---

## 2. 目标

1. 建立 `.openclaw/` 标准目录，任意项目 3 分钟可接入
2. 定义四文件契约（README.md / metadata.json / SKILL.md / TODO.md），Agent 零成本理解项目
3. 写死人机协同协议：用户分配 → Agent 执行 → 举手写入 TODO → 用户协调 → 插件督促
4. 修复 3 个插件 Hook（regulation / monitoring / working-memory）

```
## 关键文件索引

| 文件 | 用途 |
|------|------|
| `metadata.json` | 项目结构、模块列表、Agent 能力 |
| `TODO.md` | 当前任务看板 |
| `docs/COLLABORATION.md` | 协作标记规范 |
| `.openclaw/events/` | 最近发生了什么 |

## 快速开始（Agent 必读）

1. 读取 `metadata.json` 理解项目结构
2. 读取 `TODO.md` 理解当前任务
3. 读取 `.openclaw/events/{今天}.md` 了解最近事件
4. 执行任务，产出到 `manuscripts/`
5. 完成后请求用户确认，确认后移到 `docs/`
```

- 完成者将任务移到「待确认」并通知用户

### 3.6 .openclaw/events/（格式规范）

文件命名：`{YYYY-MM-DD}.md`

内容格式：
```markdown
# 2026-05-08 事件流

- 18:00 用户: 分配「任务3」给 @main
- 18:05 main: 制定计划，创建 .openclaw/ 目录
- 18:10 main: 完成 README.md 和 metadata.json
- 18:12 main: 举手，写入 TODO.md「待分配（用户协调）」— 需要视觉 Agent
```

**规则**：
- 只追加，不删除
- 每行格式：`- {HH:MM} {who}: {what}`
- 跨天事件在新文件继续

### 3.7 .openclaw/locks/（格式规范）

文件命名：将文件路径中的 `/` 替换为 `-`，如 `docs-README.md.json`

内容格式：
```json
{
  "file": "docs/README.md",
  "agent": "main",
  "since": "18:00",
  "expires": "18:10",
  "reason": "编辑 README"
}
```

**规则**：
- Agent 编辑前创建，完成后删除
- 10分钟自动过期（expires = since + 10min）
- 冲突检测：编辑前检查同名锁文件，若存在则向用户报告

### 3.8 COLLABORATION.md（标记规范，复制可用）

```markdown
# 协作标记规范

## 状态标记
| 标记 | 谁用 | 含义 |
|------|------|------|
| `[SELF_CHECKED]` | 执行者 | 自检完成 |
| `[HELP: 需求]` | 执行者 | 需要其他 Agent，已写入 TODO |
| `[BLOCKED]` | 执行者 | 等用户输入，不阻塞其他任务 |
| `[APPROVED]` | 用户 | 确认通过 |
| `[REJECTED]` | 用户 | 拒绝，需修正 |
| `[USER_BLOCK]` | 用户 | 暂停/终止 |

## 文档标记
| 标记 | 谁用 | 含义 |
|------|------|------|
| `[DOC_UPDATE: 文件名]` | 执行者 | 更新了文档 |
| `[DOC_SKIP]` | 执行者 | 无需更新 |
```

## 4. 人机协同协议（具体流程）

### 4.1 用户分配任务

```
用户："main，你擅长系统配置，帮我初始化这个项目"
→ main 读取 uploads/（用户可能上传了资料）
→ main 读取 TODO.md，确认任务
→ main 回复："收到，我将按以下步骤执行：1.创建目录 2.写四文件 3.汇报"
```

### 4.2 Agent 举手请求协助

```
main 执行中发现需要图像识别能力：
→ main 继续执行自己擅长的部分（不停止）
→ main 在 TODO.md 添加：
   ## 待分配（用户协调）
   - [ ] 子任务：Logo识别 — 需要擅长视觉的Agent — 举手者：@main
→ main 向用户汇报：
   "数据分析部分我来做。但发现需要Logo识别，建议分配给擅长视觉的Agent。
   我已写入TODO，请协调。"
→ 用户看到后将子任务分配给另一个Agent
→ 两个Agent通过 manuscripts/ 和 docs/ 共享文件（不通过 sessions_send）
```

### 4.3 插件督促时机（具体注入内容）

| 时机 | 插件注入的原文 | Agent 必须做的事 |
|------|---------------|------------------|
| 任务启动 | `【计划提醒】请制定执行计划，列出：1.步骤 2.验收标准 3.预估时间。然后向用户汇报。` | 输出计划，等用户确认再执行 |
| 执行中 | `【进度提醒】请向用户汇报当前进度：完成了什么、遇到了什么问题、下一步做什么。` | 汇报进度，不沉默执行 |
| 文件变更后 | `【协作提醒】检测到文件变更：{文件名}。请判断：是否需要其他Agent协助？如需，写入TODO并举手。` | 评估是否需要举手 |
| 完成前 | `【验收提醒】任务即将完成。请自检：1.是否满足用户需求 2.是否需要更新文档。然后向用户请求确认。` | 自检，输出 `[SELF_CHECKED]`，请求确认 |

## 5. 插件 Hook 修复（具体代码）

### 5.1 修复 regulation 注入

**文件**：`src/metacognition/module.js`

**当前问题**：
```javascript
// 第 X 行：regulation 被实例化但未调用
this.deviation = new Deviation();     // 创建了但没用
this.attribution = new Attribution(); // 创建了但没用
// regulation/SKILL.md 从未被加载
```

**修复方案**：在 `_buildExecutionContext` 中添加：
```javascript
// 在 _buildExecutionContext 方法中，监控注入后添加：
if (task.deviations && task.deviations.length > 0) {
  const regulationSkill = this.skills.get('regulation');
  if (regulationSkill) {
    const unhandledDeviations = task.deviations.filter(d => !d.handled);
    if (unhandledDeviations.length > 0) {
      planningContext += `\n【偏差处理】以下偏差尚未处理：\n${unhandledDeviations.map(d => `- ${d.type}: ${d.description}`).join('\n')}\n请按 regulation skill 进行归因分析。`;
    }
  }
}
```

**验收标准**：当 `task.deviations` 有未处理项时，Agent 收到 regulation skill 内容。

### 5.2 重写 monitoring 职责

**文件**：`src/metacognition/module.js`

**当前问题**：monitoring 在 `before_prompt_build` 注入，但此时本轮输出还没生成，Agent 看不到「上轮输出 vs 预期」的对比。

**修复方案**：不改变注入时机，但改变注入内容：
```javascript
// 修改 monitoring skill 的注入内容，从"检测偏差"改为"预防偏差"
// 原内容（删除）：
// "请检查上轮输出是否符合预期..."

// 新内容：
// "当前阶段目标：{task.plan.execution.phases[currentPhase].goal}
// 历史偏差：{task.deviations.slice(-3).map(...)}
// 本轮执行后，若发现偏差，请输出 [STATUS: revising]"
```

**验收标准**：Agent 收到的是「当前目标 + 历史偏差摘要」，而非「请检测上轮输出」。

### 5.3 working-memory 轻量注入

**文件**：`src/working-memory/module.js`

**当前问题**：只注册了 `after_tool_call` / `agent_end`，没有 `before_prompt_build`，Agent 创建子代理时不知道 Session 规则。

**修复方案**：添加钩子：
```javascript
// 在 module.js 构造函数中注册：
this.hooks = [
  { name: 'before_prompt_build', handler: this.onBeforePromptBuild.bind(this) },
  { name: 'after_tool_call', handler: this.onAfterToolCall.bind(this) },
  { name: 'agent_end', handler: this.onAgentEnd.bind(this) }
];

// 新增方法：
onBeforePromptBuild(task, context) {
  // 只注入5条核心规则（而非完整173行）
  const sessionRules = `
【Session管理规则】
1. 优先复用 idle Session（同 taskFamily）
2. 创建新 Session 时记录 purpose 和预计完成时间
3. 子代理完成后必须销毁 Session（避免僵尸）
4. 如需要完整规则，请读取 working-memory/SKILL.md
5. 如需推荐 Session，请在 Plan 中说明任务类型
  `;
  
  // 仅在涉及 session 操作时注入
  if (task.toolsAllow && task.toolsAllow.includes('sessions')) {
    context.planning += sessionRules;
  }
}
```

**验收标准**：Agent 执行涉及 session 的操作前，收到 5 条核心规则。

### 5.4 Session 推荐接口

**文件**：`src/working-memory/session.js`

**当前问题**：`createSession` 每次生成新 ID。

**修复方案**：新增推荐方法（不修改 createSession）：
```javascript
// 新增方法：
static recommendSessions(taskFamily, globalIndex) {
  const activeSessions = globalIndex.get('working_memory:active_sessions') || [];
  return activeSessions
    .filter(s => s.taskFamily === taskFamily && s.status === 'idle')
    .map(s => ({
      sessionId: s.sessionId,
      idleSince: s.lastActive,
      purpose: s.purpose
    }));
}

// 在 planning 阶段由插件调用：
// planningContext += `\n【可复用Session】${JSON.stringify(recommendations)}`;
```

**验收标准**：planning skill 注入时，Agent 收到可复用 Session 列表。
