> **核心定位**：借鉴 self-improving-agent 条件触发机制，优化 Hook 注入时机，实现精准提醒。

## 一、版本目标

### 为什么优化 Hook 时机？

v4.4.0 及之前的 Hook 机制依赖标准事件（`session_start` / `after_compaction` / `before_prompt_build`），无法精准对应业务时机：
- `session_start` 只在 compaction 时触发
- `before_prompt_build` 每次 prompt 构建都触发，过于频繁
- 两者都无法在「任务创建/偏差记录/事件生成」等关键节点触发

**v4.5.0 的新定位**：
- **条件触发**：通过 `after_tool_call` 监听关键工具返回值，条件触发提醒
- **精准时机**：只在业务关键节点触发，不打扰正常执行
- **借鉴最佳实践**：参考 self-improving-agent 的 `PostToolUse` 机制

## 二、需求分析

### 原始需求（用户输入）

1. 在 event 相关 tool 调用后，注入自我调节提醒
2. 在 task.update 调用后，注入偏差分析 + 归因分析提醒
3. 在任务创建后，注入创建任务提醒
4. 在执行内容时（无任务上下文），注入要创建任务的提醒

### 核心问题

当前 Hook 时机太粗糙，无法精准对应业务时机。

### 技术方向

通过 `after_tool_call` 监听关键工具返回值，条件触发提醒注入。

---

## 三、关键决策

### 决策 1：采用 after_tool_call 条件触发

**原因**：标准事件不够精准。`after_tool_call` 提供了工具调用结果，可以解析返回值判断是否需要触发提醒。

**实施要点**：
- 解析 `event.toolName` 确定工具类型
- 解析 `event.result` 内容判断返回值状态
- 使用 idempotencyKey 避免重复注入

### 决策 2：保留 before_prompt_build 但降低频率

**原因**：`before_prompt_build` 仍然需要，用于检测「无任务执行」场景。

**实施要点**：
- 只在无 active task 时触发
- 有 active task 时跳过，避免打扰

### 决策 3：沿用现有注入内容

**原因**：event.md 模板已包含六维度判断框架，HOOK.md 已定义注入内容，无需修改。

## 四、注入时机矩阵

| # | 触发时机 | 监听工具 | 条件 | 注入内容 | IdempotencyKey |
|---|----------|----------|------|----------|----------------|
| M1 | 任务创建后 | `task.create` | 返回成功 | 提醒：制定计划 → 拆解 TODO | `reg:task-created` |
| M2 | 偏差记录后 | `task.update` | 检测到 deviation 字段 | 提醒：执行偏差分析 → 归因分析 | `reg:deviation-detected` |
| M3 | 事件生成后 | `event.report` | 返回成功 | 提醒：六维度平衡性判断 | `reg:event-generated` |
| M4 | 无任务执行时 | `before_prompt_build` | 检测无 active task | 提醒：创建任务 | `reg:no-active-task` |

---

## 五、技术实现路径

```
after_tool_call hook
    ↓
解析 event.toolName + event.result
    ↓
条件匹配
    ├── task.create → idempotencyKey: 'reg:task-created'
    ├── task.update (含 deviation) → idempotencyKey: 'reg:deviation-detected'
    └── event.report → idempotencyKey: 'reg:event-generated'
    ↓
enqueueNextTurnInjection(perIdempotencyKey)
```

## 七、风险与缓解

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 条件判断逻辑错误导致重复注入 | 🟡 中 | 使用 idempotencyKey 去重；每个场景单独测试 |
| before_prompt_build 降频逻辑影响其他插件 | 🟡 中 | 只检查 active task，不做其他逻辑；其他插件不受影响 |
| event.result 解析失败 | 🟡 中 | try-catch 包裹；解析失败时跳过，不阻塞 |
