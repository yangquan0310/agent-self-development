# v4.0.1 Roadmap: 项目元数据目录命名规范化

> **核心目标**：将 `.openclaw/` 与 `.openclawignore` 重命名为与项目标识一致的 `.agent/` 与 `.agentignore`，消除命名歧义。
> **状态**：draft
> **创建时间**：2026-05-09
> **预计完成**：2026-05-09

---

## 设计目标

1. **命名一致性**：项目元数据目录与文件名应直接反映项目核心标识（agent），而非底层平台名称（openclaw）
2. **降低认知成本**：新 Agent 进入项目时，`.agent/` 比 `.openclaw/` 更直观
3. **零功能变更**：本次更新仅为全局字符串替换，不修改任何业务逻辑或数据模型
4. **版本对齐**：v4.0.0 引入项目上下文层时尚未稳定，在正式发布前完成命名修正

---

## 问题诊断

### 问题 1：元数据目录名与项目标识脱节

**影响范围**：文档 / 源码 / 技能 / 协作协议
**风险等级**：中等
**具体表现**：
- 项目名称是 `agent-self-development`，但项目级元数据目录命名为 `.openclaw/`，容易让 Agent 误以为是 OpenClaw 平台目录而非项目自有的协作层
- `.openclawignore` 过长，且风格与业界通用的 `.gitignore`、`.dockerignore` 等不一致
- 四文件契约中 `README.md`、`metadata.json`、`SKILL.md`、`TODO.md` 均使用简洁的项目相关命名，唯独元数据层使用了平台相关命名

### 问题 2：命名不一致导致文档维护负担

**影响范围**：文档
**风险等级**：低
**具体表现**：
- v4.0.0 Roadmap（1069 行）中 `.openclaw` 出现超过 100 次
- 6 份 reference 文档、5 份技能文档、3 份 Agent 角色文档均包含硬编码路径
- 后续若再调整命名，文档同步成本极高

---

## 解决方法与决策

### 问题 1 & 2 解决方案：全局重命名为 `.agent/` 与 `.agentignore`

**方案**：将 `.openclaw/` → `.agent/`，`.openclawignore` → `.agentignore`，并全局同步所有引用
**决策依据**：
- 方案 A（保持现状）：命名歧义持续存在，与新 Agent 协作时反复解释 → 排除
- 方案 B（改为 `.asd/`）：缩写不直观，无法自解释 → 排除
- 方案 C（改为 `.agent/`）：直接对应项目标识，语义清晰，与 `.git/` 等目录命名风格一致 → **选用**
**实施要点**：
1. 列出所有受影响文件（文档、源码、技能、测试）
2. 按「源码 → 技能 → 文档 → 归档」顺序执行替换
3. 历史归档文件（changelog、test/reports）标注 `[ARCHIVE]`，原则上不修改内容，仅更新后续引用
4. 验证：全局搜索确认无残留 `.openclaw` 引用
**兼容性**：[BREAKING] — 对已按 v4.0.0 协议初始化 `.openclaw/` 目录的项目，需要手动重命名。由于 v4.0.0 尚未正式发布（状态 active），此变更在发布前完成。
