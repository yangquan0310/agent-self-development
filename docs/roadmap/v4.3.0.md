# v4.3.0 路线图：Object-Driven Tool Plugin

> **类型**：版本路线图  
> **版本**：v4.3.0  
> **日期**：2026-05-19  
> **状态**：🚧 规划中  
> **核心定位**：从「全功能认知框架」退回到「工具插件」——只暴露工具，让 Agent 自主调用完成 task + event 全生命周期管理。

---

## 一、版本目标

### 为什么改变架构？

v4.2.0 及之前的架构是一个「重框架」——包含元认知模块、工作记忆模块、人格模块、Hook 注入、Heartbeat 等。这个架构过于复杂，与 OpenClaw 新插件规范「工具插件」的定位不符。

**v4.3.0 的新定位**：
- **纯工具插件**：只通过 `api.registerTool()` 暴露工具，不做 Hook 注入、不做认知框架
- **对象驱动**：TaskObject + EventObject 是核心，管理 `.agent/tasks/` 和 `.agent/events/` 的全生命周期
- **Agent 自主**：Agent 自行决定何时创建任务、何时记录事件、何时推进阶段、何时归档
- **极简目录**：`src/` 下只保留 `objects/`、`assets/`、`tools/`、`utils/`

---

## 二、工具需求

### 任务管理工具

v4.3.0 应暴露**任务全生命周期管理工具**，使 Agent 能够：
- 创建任务（初始化 task.json）
- 更新任务状态
- 推进任务阶段
- 查询任务完整状态
- 归档已完成任务

### 事件报告工具

v4.3.0 应暴露**事件报告工具**，使 Agent 能够：
- 在任务完成后生成事件总结报告（从 task.json 凝练生成 event.md）
- 查询历史事件报告

**不暴露的工具**：认知指导类工具（planning/monitoring/regulation/development）——Agent 自行决策，插件不提供指导。

---

## 三、关键决策

### 决策 1：移除认知指导类工具

**原因**：v4.2.0 的 planning / monitoring / regulation / development 工具是「插件替 Agent 决策」的残留。在工具插件哲学下，Agent 应该自行决定如何规划、如何监控、如何调节——插件只提供数据（task 查询 / event 查询），不提供指导。

### 决策 2：移除 Hook 注入层

**原因**：工具插件不注入 Hook、不修改 Agent prompt。Agent 通过工具调用主动获取信息，插件被动响应。

### 决策 3：保留 task.json 和 event.md 的契约

**原因**：这是项目上下文层的核心资产。即使插件精简，`.agent/tasks/` 和 `.agent/events/` 的文件格式契约必须保留，确保 Agent 可以跨插件/跨项目理解这些文件。

### 决策 4：event.md 延迟凝练

**原因**：执行过程中偏差/归因/结果只写入 task.json，任务完成后一次性从 task.json 凝练生成 event.md。避免执行过程中频繁写 event.md 带来的性能开销和数据不一致风险。
