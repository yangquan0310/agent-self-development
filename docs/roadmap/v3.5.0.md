## 设计目标

1. **合规优先**：修复所有 hooks 使用违反官方文档规范的问题（观察型钩子禁止返回注入）
2. **闭环修复**：重构 NEED_PLAN 检测 → Plan 制定的闭环，使用合规钩子替代违规注入
3. **运行时稳定**：修复 4 个运行时 bug（crypto 未导入、硬编码配置、ID 语义错误、内存泄漏）
4. **框架扩展**：引入官方新钩子（subagent 生命周期、heartbeat 监控、before_agent_finalize 质量检查）
5. **代码清理**：删除冗余代码（event.js、未使用 import），修正自检数据

## 问题诊断（18 项，完整清单）

### 第一类：Hooks 使用不合规（违反官方文档，3 项）

官方文档明确区分：
- **观察型钩子**（非粗体）：`llm_output`、`agent_end`、`llm_input`、`model_call_started/ended` → **仅观察，禁止返回系统上下文**
- **决策/注入型钩子**（粗体）：`before_prompt_build`、`before_agent_reply`、`before_agent_finalize`、`before_tool_call` → **可返回决策/注入**

| # | 问题 | 当前实现 | 违规原因 |
|---|------|----------|----------|
| 1 | `llm_output` 注入 monitoring skill | `onLlmOutput` task=active 时返回 `prependSystemContext: monitoringSkill` | `llm_output` 为观察型钩子，禁止返回注入 |
| 2 | `llm_output` 注入 planning skill | 检测到 `[NEED_PLAN]` 后返回 `prependSystemContext: planningSkill` | 同上，且该机制需迁移至合规钩子 |
| 3 | `agent_end` 注入 skill | `WorkingMemory.onAgentEnd` 注入 `working_memory` skill；`Personality.onAgentEnd` 注入 `development` skill | `agent_end` 为观察型钩子，30s 超时即发即弃，禁止返回注入 |

#### 1.4 NEED_PLAN 闭环重构（核心变更）

**`before_agent_finalize` 直接检测输出内容**：

```javascript
async onBeforeAgentFinalize(event, ctx) {
  // 从 event 获取完整输出
  const output = event.output || event.text || '';
  
  // 检测 NEED_PLAN 标记
  if (output.includes('[NEED_PLAN]')) {
    // 创建 draft task
    const task = await this.plan.createTask({ prompt: output, runId: ctx.runId });
    
    // 加载 planning skill
    const planningSkill = await this.skills.load('planning');
    
    return {
      action: "revise",
      reason: "检测到 NEED_PLAN 标记，需要制定 Plan",
      retry: {
        instruction: `请根据以下 planning skill 制定完整 Plan：\n${planningSkill}`,
        maxAttempts: 2
      }
    };
  }
  
  // 其他检测场景（见 1.6）
  // ...
  
  return { action: "finalize" };
}
```

**闭环流程**：
```
Agent 输出回复（含 [NEED_PLAN]）
    │
    ▼
llm_output（纯观察）→ 保存输出到缓冲/日志
    不检测标记，不返回注入
    │
    ▼
before_agent_finalize（决策）→ 读取输出内容 → 检测到 [NEED_PLAN]
    → 创建 draft task → 返回 action: "revise"
    │
    ▼
Harness 追加 instruction + planning skill → 第二次模型传递
    │
    ▼
Agent 修订回复（制定 Plan）→ 用户视觉上为同一条回复
    │
    ▼
before_agent_finalize → 无 NEED_PLAN → action: "finalize"
```

- [ ] 在 `before_agent_finalize` 中实现 NEED_PLAN 检测逻辑（直接检查输出内容）
- [ ] 检测到后创建 draft task，返回 `action: "revise"` + planning skill
- [ ] 设置 `maxAttempts: 2`，避免无限修订循环

#### 1.7 状态转换与标记机制（核心原则：Agent 决策，插件记录）

**核心原则**：用户确认方向 → Agent 决策执行 → 插件检测标记并记录。

**Prompt 暂存机制**：
```javascript
// before_prompt_build 中保存用户原始需求
async onBeforePromptBuild(event, ctx) {
  // 保存用户原始 prompt，供 before_agent_finalize 创建 task 时使用
  if (event.prompt) {
    ctx.state.set(`prompt:${ctx.runId}`, event.prompt);
  }
  // ... 其余逻辑
}

// before_agent_finalize 中读取
async onBeforeAgentFinalize(event, ctx) {
  if (output.includes('[NEED_PLAN]')) {
    const prompt = ctx.state.get(`prompt:${ctx.runId}`) || output;
    const task = await this.plan.createTask({ prompt, runId: ctx.runId });
    // ...
  }
}
```

**状态转换检测**（Agent 在输出中标记状态变更）：

| 状态转换 | Agent 输出标记 | 插件检测 | 插件操作 |
|----------|---------------|----------|----------|
| draft → pending_approval | `[STATUS: pending_approval]` | `before_agent_finalize` | `task.status = "pending_approval"` → `State.saveTask()` |
| pending_approval → active | `[STATUS: active]` | `before_agent_finalize` | `task.status = "active"` → `State.saveTask()` |
| active → revising | `[STATUS: revising] [REASON: ...]` | `before_agent_finalize` | `task.status = "revising"`；`task.revisionReason = "..."` → `State.saveTask()` |
| pending_approval → completed（取消） | `[STATUS: completed]` | `before_agent_finalize` | `task.status = "completed"` → `State.saveTask()` → 触发 agent_end 归档 |
| active → completed | `[STATUS: completed]` | `before_agent_finalize` | `task.status = "completed"` → `State.saveTask()` → 触发 agent_end 归档 |

**Agent 输出示例**：
```
用户已确认 Plan，现在开始执行。
[STATUS: active]
```

```
用户要求增加测试阶段，需要重新制定 Plan。
[STATUS: revising]
[REASON: 用户要求增加测试阶段]
```

### 详细说明

#### `before_prompt_build` —— 注入型，由 Metacognition + Personality 处理

```
metacognition/module.js onBeforePromptBuild(event, ctx)
├── 无 task ──→ 返回 { prependSystemContext: planningSkill（评估阶段） }
├── task=draft ──→ 返回 { prependSystemContext: planningSkill（制定阶段）+ 草案上下文 }
├── task=pending_approval ──→ 返回 { prependSystemContext: planningSkill（汇报阶段）+ 当前Plan }
├── task=revising ──→ 返回 { prependSystemContext: planningSkill + 修改原因 }
└── task=active ──→ 返回 { prependSystemContext: monitoringSkill + 执行上下文 }

personality/module.js onBeforePromptBuild(event, ctx)（新增）
└── 无 task + 近期有 completed ──→ 返回 { prependSystemContext: developmentSkill }（可选追加）
```

#### `llm_output` —— 观察型，由 Metacognition 处理

```
metacognition/module.js onLlmOutput(event, ctx)
├── 流式 chunk ──→ Stream.accumulate()，返回 undefined
├── 流结束/full ──→ Stream.drain()，保存输出到 Log
└── 不检测 [NEED_PLAN]，不写入 task，不返回任何注入
```

#### `before_agent_finalize` —— 决策型，由 Metacognition 处理（新增）

```
metacognition/module.js onBeforeAgentFinalize(event, ctx)
├── 含 [NEED_PLAN] ──→ State.saveTask(draft) → 返回 { action: "revise", retry: { instruction, maxAttempts: 2 } }
├── 含 TODO/FIXME ──→ 返回 { action: "revise", ... }
├── 输出不完整 ──→ 返回 { action: "revise", ... }
├── 关键步骤缺失 ──→ 返回 { action: "revise", ... }
└── 正常 ──→ 返回 { action: "finalize" }
```

#### `before_tool_call` / `after_tool_call` —— 由 WorkingMemory 处理

```
working-memory/module.js onBeforeToolCall(event, ctx)
└── 所有工具调用 ──→ task.tools.push({ toolName, params, timestamp }) → State.saveTask()
    注意：不再区分是否子代理，子代理的 Session 管理由 subagent_* 钩子负责

working-memory/module.js onAfterToolCall(event, ctx)
└── 工具执行后 ──→ task.tools.push({ toolName, result, timestamp }) → State.saveTask()
    注意：不再区分是否子代理，子代理状态同步由 subagent_ended 负责
```

#### `agent_end` —— 观察型，三个模块各自处理

```
working-memory/module.js onAgentEnd(event, ctx)
├── 遍历 task.sessionIds ──→ 更新活跃会话索引
├── task.status = "completed" ──→ State.saveTask()
├── Event.archiveTask(runId) ──→ 读取 task JSON → 打包成事件 → Memory.appendEventLog()
└── State.archiveTask(runId) ──→ 归档到 archive/
    返回 undefined（v3.5.0 移除 working_memory skill 注入）

metacognition/module.js onAgentEnd(event, ctx)
├── Stream.purge(runId) ──→ 清理流式缓冲
└── _injectCount.delete(runId) ──→ 清理注入计数
    返回 undefined

personality/module.js onAgentEnd(event, ctx)
└── Log.write() ──→ 记录 completed 日志
    返回 undefined（v3.5.0 移除 development skill 注入）
```

#### `subagent_*` —— 观察型，由 WorkingMemory 处理（新增）

```
working-memory/module.js onSubagentSpawning(event, ctx)
└── ctx.state.set(`subagent:${taskFamily}`, { status: 'spawning' })

working-memory/module.js onSubagentSpawned(event, ctx)
└── task.sessionIds.push(sessionKey) → State.saveTask()

working-memory/module.js onSubagentEnded(event, ctx)
└── task.subagentStatus[event.taskFamily] = status → State.saveTask()
```

#### `heartbeat_prompt_contribution` —— 注入型，由 Heartbeat 处理（新增）

```
common/heartbeat.js onHeartbeatPromptContribution(event, ctx)
└── 返回 { prependSystemContext: "【后台状态】活跃任务：X，待处理偏差：Y..." }
```

#### `gateway_stop` —— 由 Memory 适配器处理（新增）

```
memory.js close()
└── db.close() → 关闭 SQLite 连接
```

## 关键设计决策

### 为什么 monitoring skill 要从 llm_output 迁移到 before_prompt_build？
- 官方文档明确 `llm_output` 为观察型钩子，不应返回系统上下文
- `before_prompt_build` 是设计用于"在模型调用前添加动态上下文"的钩子
- monitoring 指导 Agent 在生成回复前检查 Plan 一致性，时机上更符合 before_prompt_build

### 为什么 personality skill 要从 agent_end 移除？
- 官方文档明确 `agent_end` 为观察型钩子，"即发即弃"，30秒超时
- agent_end 后 Agent 不再生成输出，返回 `prependSystemContext` 无意义
- 人格更新应在 Agent 开始新回合时（before_prompt_build）注入 development skill，让 Agent 在制定新 Plan 前回顾上一次经验

### NEED_PLAN 闭环为什么要用 before_agent_finalize 而不是 llm_output 直接注入？
- 官方约束：`llm_output` 为仅用于观察的钩子，不应返回系统上下文
- `before_agent_finalize` 专门设计用于"在 harness 接受最终答案前检查并修订"
- 使用 `action: "revise"` 是官方推荐的质量控制机制，Harness 会自动追加 instruction 并执行第二次传递
- 用户视觉上仍为同一条回复（修订传递无缝衔接）

### 为什么 `before_agent_finalize` 直接检测输出而不是通过 `llm_output` 传递状态？
- `llm_output` 是观察型钩子，职责应单一：只看、只记
- `before_agent_finalize` 是决策型钩子，天然适合做质量检查和内容分析
- 直接检测省去状态传递的中间层，代码更简洁，职责边界更清晰
- `before_agent_finalize` 能访问完整输出（`event.output`），无需 `llm_output` 预处理

### development skill 注入频率为什么要控制？
- 每次对话都注入 development skill 会稀释上下文，干扰 Agent 对当前任务的专注
- 频率控制（每个 session 最多每 3 次对话）平衡了经验回顾和上下文效率
- 备选方案（Agent 自行读取 MEMORY.md）更干净，但需要 Agent 具备主动回顾能力

### 核心业务流程（按阶段）

#### 阶段 1：任务评估（无 task）

1. `before_prompt_build` → Metacognition 注入 planning skill（评估阶段）
2. Personality 可选追加 development skill
3. Agent 评估：简单任务直接回答，复杂任务输出 `[NEED_PLAN]`

#### 阶段 2：Plan 制定（NEED_PLAN → draft → pending_approval）

1. `before_prompt_build` → Metacognition 保存用户原始 prompt 到 `ctx.state`
2. `llm_output` → Metacognition 纯观察，只保存输出
3. `before_agent_finalize` → Metacognition 检测 `[NEED_PLAN]` → 从 `ctx.state` 读取 prompt → 创建 task（draft）→ 返回 revise
4. Harness 追加 instruction → Agent 修订传递中制定 Plan
5. Agent 输出 `[STATUS: pending_approval]` → `before_agent_finalize` 更新 task.status → 状态转换：draft → pending_approval

#### 阶段 3：Plan 审核（pending_approval）

1. `before_prompt_build` → Metacognition 注入 planning skill（含当前 Plan）
2. Agent 汇报 Plan，用户确认/修改/取消
3. Agent 输出状态标记：
   - 确认 → `[STATUS: active]` → `before_agent_finalize` 更新 task.status = "active"
   - 修改 → `[STATUS: pending_approval]` → 保持 pending_approval，重新制定
   - 取消 → `[STATUS: completed]` → `before_agent_finalize` 更新 task.status = "completed"

#### 阶段 4：任务执行（active）

1. `before_prompt_build` → Metacognition 注入 monitoring skill + 执行上下文
2. Agent 执行，自查偏差 → 记录到 `task.deviations[]`
3. Agent 输出状态标记：
   - 阶段完成 → `[STATUS: active]`（currentPhase++）
   - 全部完成 → `[STATUS: completed]`
   - 重大偏差需重规划 → `[STATUS: revising] [REASON: ...]`

#### 阶段 5：任务完成与归档（completed）

1. `agent_end` → WorkingMemory 归档 task → `State.archiveTask()`
2. `agent_end` → Event.archiveTask(runId)：读取 task JSON（含 deviations/attributions）→ 打包成事件 → `Memory.appendEventLog()`
3. `agent_end` → Metacognition 清理缓冲
4. `agent_end` → Personality 记录 completed 日志（不查询 Memory）

#### 阶段 6：人格回顾（下次任务开始时）

1. `before_prompt_build` → Personality 检测近期 completed task → 注入 development skill
2. Agent 从 Memory.queryEventLog() 读取历史事件 → 更新人格文件

### 数据流总结

| 阶段 | 写入者 | 写入位置 | 读取者 |
|------|--------|----------|--------|
| 评估 | Metacognition | — | Agent（通过 skill） |
| Prompt 暂存 | Metacognition | `ctx.state` | `before_agent_finalize`（创建 task 时读取） |
| Plan 制定 | Plan.createTask() | `state/tasks/{runId}.json` | Metacognition / Agent |
| 状态转换 | Agent（标记）→ `before_agent_finalize`（记录） | `state/tasks/{runId}.json` | Metacognition / Agent |
| 执行监控 | Agent（自查） | `task.deviations[]` / `task.attributions[]` | Event（打包时读取） |
| 任务归档 | WorkingMemory | `archive/tasks_archive.json` | — |
| 事件归档 | Event.archiveTask() | `memory/{agentId}.sqlite` | Personality（人格更新） |
| Session 管理 | WorkingMemory | `state/sessions.json` | WorkingMemory |
| 日志 | 各模块 | `logs/{agentId}.log` | 开发者调试 |
