# Changelog: v4.1.0 — Tool-Driven Agent Autonomy

> **发布日期**：2026-05-20（预计）
> **版本代号**：Tool-Driven Agent Autonomy
> **维护者**：PM + Developer
> **状态**：RC

---

## 1. 版本概述

v4.1.0 是 `agent-self-development` 插件的架构级升级版本，核心目标是从 **"Hook 注入 Skill"** 架构迁移到 **"Tool 暴露 + Agent 自主调用"** 架构。

**解决的问题**：
- 插件职责越界：代替 Agent 做决策、自动创建 task、维护复杂状态机
- Agent 被动接收：无法主动查看其他阶段的指导，system context 膨胀
- 隐式标记通信：`[STATUS]`/`[NEED_PLAN]` 标记解析脆弱
- 与生态脱节：主流插件（飞书官方）均采用 `api.registerTool()` 暴露能力

**架构变革**：
```
v4.0.0（推送式）                    v4.1.0（自主式）
┌─────────────────┐              ┌─────────────────┐
│ 插件决定注入什么 │              │ 插件暴露 Tools  │
│ Agent 被动接收   │      →      │ Agent 主动调用  │
└─────────────────┘              └─────────────────┘
```

## 2. 破坏性变更清单（BREAKING CHANGES）

### 2.1 `.openclaw` 目录重命名为 `.agent`

**影响等级**：🔴 高
**说明**：所有项目级和系统级路径从 `.openclaw/` 统一改为 `.agents`。

| 旧路径 | 新路径 |
|--------|--------|
| `.openclaw/` | `.agents` |
| `.openclawignore` | `.agentignore` |
| `~/.openclaw/tasks/` | `~/.agentstasks/` |
| `~/.openclaw/events/` | `~/.agentsevents/` |
| `~/.openclaw/logs/` | `~/.agentslogs/` |

**迁移步骤**：
```bash
# 1. 重命名项目级目录
mv .openclaw .agent
mv .openclawignore .agentignore

# 2. 重命名用户主目录下的系统级目录
mv ~/.openclaw ~/.agent

# 3. 检查残留（项目中不应再有 .openclaw 引用）
grep -r "\.openclaw" . --include="*.js" --include="*.md" --include="*.json"
```

### 2.2 `before_prompt_build` 注入大幅简化（tool-driven 模式）

**影响等级**：🟡 中
**说明**：默认不再注入完整 skill 文本，仅输出最小化提示（状态 + tools 列表）。

**受影响状态**：
- 无 task：原注入完整 planning skill → 现仅注入 1-2 句提示
- draft：原注入 planning skill + 文件上下文 → 现仅注入状态摘要
- active：原注入 monitoring + regulation + 执行上下文 → 现仅注入状态摘要

**回退方案**：
在 `openclaw.plugin.json` 中将 `injectionMode` 设为 `"legacy"`：
```json
{
  "config": {
    "injectionMode": "legacy"
  }
}
```

### 2.3 插件不再自动创建 task

**影响等级**：🟡 中
**说明**：检测到 `[NEED_PLAN]` 后，插件不再自动创建 draft task。

**行为变化**：
| 场景 | v4.0.0 | v4.1.0 |
|------|--------|--------|
| Agent 输出 `[NEED_PLAN]` | 插件自动创建 draft task | 返回 `action: "revise"`，提示使用 `create_plan` tool |
| Agent 输出 `[STATUS: active]` | 插件自动更新 status | 保留解析（deprecated），推荐用 `update_task_status` |

## 3. 迁移指南

### 3.1 从 `[STATUS]` 标记迁移到 Tool 调用

**旧方式（v4.0.0，已废弃）**：
```markdown
用户确认后，我将开始执行。
[STATUS: active]
```

**新方式（v4.1.0，推荐）**：
```javascript
// Agent 调用 update_task_status tool
const result = await tools.update_task_status({
  runId: 'current-task',
  status: 'active',
  reason: '用户确认'
});
// result: { success: true, runId: 'current-task', status: 'active' }
```

**对应关系表**：

| 旧标记 | 新 Tool 调用 | 说明 |
|--------|-------------|------|
| `[NEED_PLAN]` | `create_plan({ runId, prompt, planInput })` | 创建 draft task |
| `[STATUS: pending_approval]` | `update_task_status({ runId, status: 'pending_approval' })` | 提交 Plan 待确认 |
| `[STATUS: active]` | `update_task_status({ runId, status: 'active' })` | 用户确认，开始执行 |
| `[STATUS: revising] [REASON: x]` | `update_task_status({ runId, status: 'revising', reason: 'x' })` | 进入修订 |
| `[STATUS: completed]` | `update_task_status({ runId, status: 'completed' })` | 任务完成 |
| 无标记（阶段完成） | `advance_phase({ runId })` | 推进 currentPhase |

### 3.2 从被动 Skill 注入迁移到主动 Tool 调用

**旧方式（v4.0.0）**：
- 插件根据 `task.status` 自动注入对应 skill
- Agent 被动接收，无法查看其他阶段指导

**新方式（v4.1.0）**：
- Agent 主动调用 `get_planning_guide()` / `get_monitoring_guide()` 等获取指导
- 可以随时回顾任意阶段的完整指导

**典型调用链**：
```javascript
// 1. 了解当前状态
const { task } = await tools.get_task_status({ runId: 'xyz' });

// 2. 根据状态获取指导
if (task.status === 'active') {
  const { guide, currentPhase, historyDeviations } = await tools.get_monitoring_guide({ runId: 'xyz' });
  // 按照 guide 执行
}

// 3. 推进任务
await tools.advance_phase({ runId: 'xyz' });

// 4. 记录偏差
await tools.record_deviation({
  runId: 'xyz',
  type: 'scope_creep',
  description: '用户要求增加功能',
  impact: '延期2天'
});
```

### 3.3 配置迁移

在 `openclaw.plugin.json` 中添加 `injectionMode`：

```json
{
  "id": "agent-self-development",
  "configSchema": {
    "injectionMode": {
      "type": "string",
      "enum": ["legacy", "tool-driven"],
      "default": "tool-driven",
      "description": "Skill 注入模式：legacy 保留完整注入，tool-driven 使用最小化注入 + Tool 自主调用"
    }
  }
}
```

## 4. 配置说明

### 4.1 `injectionMode`

| 模式 | 行为 | 适用场景 |
|------|------|---------|
| `"tool-driven"`（默认） | `before_prompt_build` 仅注入状态摘要 + tools 列表 | Agent 已适应 Tool 调用（推荐） |
| `"legacy"` | `before_prompt_build` 保留 v4.0.0 完整 skill 注入 | 向后兼容、Agent 尚未迁移 |

**切换方式**：
```bash
# 查看当前配置
openclaw config get plugins.entries.agent-self-development.config.injectionMode

# 切换到 legacy 模式
openclaw config patch plugins.entries.agent-self-development.config.injectionMode "legacy"

# 重启 Gateway
openclaw gateway restart
```

## 5. Tool 列表与调用示例

### 5.1 查询型 Tools（7 个）

#### `get_task_status`
```javascript
const result = await tools.get_task_status({ runId: 'task-001' });
// result: { task: { runId, status, plan, deviations, ... } }
// 或: { error: 'task 不存在: task-001' }
```

#### `get_planning_guide`
```javascript
const result = await tools.get_planning_guide({ phase: 'draft' });
// result: { guide: '【Planning Skill】...', phase: 'draft' }
// phase 可选值: assessment, draft, pending_approval, active, revising
```

#### `get_monitoring_guide`
```javascript
const result = await tools.get_monitoring_guide({ runId: 'task-001' });
// result: { guide, currentPhase, totalPhases, historyDeviations }
```

#### `self_diagnose`
```javascript
// 任务级诊断
const result = await tools.self_diagnose({ runId: 'task-001' });
// result: { diagnosis: { taskStatus: 'active', phase: 1, totalPhases: 3, deviations: 0, toolsAvailable: [...] } }

// 全局诊断
const result = await tools.self_diagnose({});
// result: { diagnosis: { mode: 'global', activeTasks: 2, completedTasks: 5, toolsAvailable: [...] } }
```

### 5.2 操作型 Tools（6 个）

#### `create_plan`
```javascript
const result = await tools.create_plan({
  runId: 'task-001',
  prompt: '帮我设计一个 API',
  planInput: {
    goal: '设计 REST API',
    constraints: ['使用 Node.js', '预算有限'],
    successCriteria: ['通过单元测试', '文档完整'],
    phases: [
      { id: 'p1', name: '需求分析', goal: '明确接口需求', outputs: ['openapi.yaml'] },
      { id: 'p2', name: '接口实现', goal: '完成代码实现', outputs: ['src/api.js'] }
    ]
  }
});
// result: { task: { runId, status: 'draft', ... }, success: true }
```

#### `update_task_status`
```javascript
const result = await tools.update_task_status({
  runId: 'task-001',
  status: 'active',
  reason: '用户确认'
});
// result: { success: true, runId: 'task-001', status: 'active', previousStatus: 'pending_approval' }
```

#### `advance_phase`
```javascript
// 默认推进到下一阶段
const result = await tools.advance_phase({ runId: 'task-001' });
// result: { success: true, previousPhase: 0, nextPhase: 1, isComplete: false, totalPhases: 2 }

// 指定 phaseId
const result = await tools.advance_phase({ runId: 'task-001', phaseId: 'p2' });
// result: { success: true, previousPhase: 0, nextPhase: 1, isComplete: false }
```

#### `record_deviation`
```javascript
const result = await tools.record_deviation({
  runId: 'task-001',
  type: 'scope_creep',
  description: '用户要求增加认证模块',
  impact: '延期1天，需新增 2 个接口'
});
// result: { success: true, deviation: { id: 'dev-1234567890', type, description, impact, timestamp, attributed: false } }
```

#### `record_attribution`
```javascript
const result = await tools.record_attribution({
  runId: 'task-001',
  rootCause: '需求评审不充分',
  impact: '返工',
  strategy: '增加需求评审环节，明确验收标准'
});
// result: { success: true, attribution: { id: 'attr-1234567890', rootCause, impact, strategy, timestamp } }
// 副作用：所有未归因偏差被标记为 attributed=true
```

#### `archive_task`
```javascript
const result = await tools.archive_task({ runId: 'task-001' });
// result: { success: true, runId: 'task-001', archivedAt: '2026-05-11T10:00:00.000Z' }
// 要求：task.status 必须为 'completed'
```

## 6. 向后兼容保证

### 6.1 Legacy 模式

通过 `injectionMode: "legacy"` 可完全恢复 v4.0.0 行为：
- `before_prompt_build` 注入完整 skill 文本
- `[STATUS]`/`[NEED_PLAN]` 标记继续被解析
- 插件行为与 v4.0.0 一致

### 6.2 Deprecated 标记

以下功能保留但标记为 deprecated，将在未来版本移除：

| 功能 | 状态 | 替代方案 |
|------|------|---------|
| `[STATUS: xxx]` 标记 | deprecated | `update_task_status()` tool |
| `[NEED_PLAN]` 标记 | deprecated | `create_plan()` tool |
| `[REASON: xxx]` 标记 | deprecated | `update_task_status({ reason })` |
| `before_prompt_build` 完整注入（legacy 模式外） | deprecated | Tool 调用获取指导 |

**deprecated 行为**：
- 检测到 `[STATUS]` 时继续解析并更新状态（日志输出 deprecated 警告）
- 检测到 `[NEED_PLAN]` 时不再自动创建 task，返回 `action: "revise"`

### 6.3 Skill 文件保留

所有 `SKILL.md` 文件保留，内容重构为可被 tool 直接返回的纯文本格式（无 frontmatter、无 Markdown 表格）。它们作为 `get_planning_guide()` / `get_monitoring_guide()` 等 tool 的文本源，不删除。

## 7. 故障排查

### 7.1 Agent 看不到 Tools 怎么办？

**症状**：Agent 回复"我没有看到任何可用的 tools"。

**排查步骤**：

1. **检查插件是否启用**：
   ```bash
   openclaw plugins list
   # 确认 agent-self-development 在列表中且状态为 active
   ```

2. **检查 api.registerTool 是否可用**：
   ```bash
   openclaw doctor
   # 确认 OpenClaw 版本 >= 2026.4.0（tool API 要求）
   ```

3. **使用 self_diagnose tool**：
   ```javascript
   const result = await tools.self_diagnose({});
   // 检查 result.diagnosis.toolsAvailable 是否包含 13 个 tools
   ```

4. **查看插件日志**：
   ```bash
   tail -f ~/.agentslogs/agent-self-development-hooks.log
   # 检查是否有 "已注册 13 个 tools" 的日志
   ```

5. **检查插件配置**：
   ```bash
   openclaw config get plugins.entries.agent-self-development
   # 确认配置正确加载
   ```

### 7.2 Tool 调用后状态未更新

**症状**：Agent 调用 `update_task_status()` 后，下次 `get_task_status()` 返回旧状态。

**排查步骤**：

1. 检查 tool handler 是否返回 `success: true`
2. 检查 `before_agent_finalize` 是否解析了 `ctx.toolCalls`
3. 查看 hooks 日志确认 State.saveTask() 是否被调用：
   ```bash
   grep "saveTask\|update_task_status" ~/.agentslogs/agent-self-development-hooks.log
   ```
4. 检查文件权限：`.agentstasks/{runId}.json` 是否可读写

### 7.3 Hook 调用链日志不输出

**症状**：`~/.agentslogs/agent-self-development-hooks.log` 为空或缺失。

**排查步骤**：

1. 检查日志目录是否存在：
   ```bash
   ls -la ~/.agentslogs/
   ```
2. 检查文件权限（插件需要写权限）
3. 确认 HookRegistry 已初始化（在 `src/common/hook.js` 中）
4. 强制触发一次对话后检查日志

## 8. 性能影响

| 变更 | 性能影响 | 说明 |
|------|---------|------|
| Tool 注册（13 个） | ~1ms 启动时开销 | 仅在插件加载时执行 |
| Hook 调用链累积 | < 1ms / hook | 内存操作，无磁盘 I/O |
| Chain flush（agent_end） | ~2ms | 单次 appendFileSync |
| 最小化注入（vs 完整注入） | 减少 50-80% 上下文长度 | 显著降低 token 消耗 |
