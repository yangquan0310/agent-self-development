# ADR-011：对象间零耦合（Tool Handler 协调模式）

> **状态**：建议中  
> **日期**：2026-05-19  
> **决策优先级**：🟡 P1  
> **可逆性**：可逆

---

## 背景

TaskObject（管理 task.json）与 EventObject（管理 event.md）在业务上存在关联：

- 记录偏差时：需同时更新 task.json 的 `deviations[]` 和 event.md 的「偏差」章节
- 记录归因时：需同时更新 task.json 的 `attributions[]` 和 event.md 的「归因」章节

存在两种协调模式可选：

**模式 A：对象间直接调用**（EventObject 内部调用 TaskObject）
**模式 B：Tool Handler 协调**（Tool Handler 分别调用两个对象）

---

## 决策

**采用模式 B：对象之间不直接调用，跨对象操作由 Tool Handler 层编排。**

```
Agent 调用 event.record
    ↓
Tool Handler (event-tools.js)
    ├── TaskObject.recordDeviation()  ──→  ./.agentstasks/{runId}.json
    └── EventObject.record()          ──→  ./.agentsevents/{date}/{time}.md
```

---

## 理由

1. **单一职责**：TaskObject 只懂 task.json，EventObject 只懂 event.md，各自不越界
2. **可测试性**：对象可独立单元测试，无需 mock 另一个对象
3. **灵活性**：Tool Handler 可灵活调整协调逻辑（如失败回滚、部分成功处理），不侵入对象内部
4. **对称性**：task.* 工具只调 TaskObject，event.* 工具以 EventObject 为主但由 Handler 协调 TaskObject，逻辑对称

---

## 边界约定

| 场景 | 操作 | 负责对象 |
|------|------|----------|
| Agent 调用 `task.create` | 创建 task.json | TaskObject |
| Agent 调用 `task.update` | 更新 task.json 状态 | TaskObject |
| Agent 调用 `task.advance` | 推进 task.json 阶段 | TaskObject |
| Agent 调用 `task.archive` | 归档 task.json | TaskObject |
| Agent 调用 `event.record` (deviation) | 追加 event.md 偏差章节 + 更新 task.json deviations[] | **Tool Handler 协调**：EventObject 写 event.md，TaskObject 写 task.json |
| Agent 调用 `event.record` (attribution) | 追加 event.md 归因章节 + 更新 task.json attributions[] | **Tool Handler 协调** |
| Agent 调用 `event.query` | 查询 event.md | EventObject |

---

## 错误处理策略

当双写之一失败时：

1. **先写 task.json，再写 event.md**
2. **task.json 写入失败**：直接返回错误，event.md 不操作
3. **event.md 写入失败**：返回错误，但 task.json 已更新不自动回滚（避免更复杂的补偿逻辑）
4. **日志记录**：Tool Handler 记录双写结果，供 Agent 诊断

> **哲学**：工具插件是「能力的提供者」，不是「事务的协调者」。Agent 收到错误后可自行决定重试或补偿。
