# ADR-010：项目级文件系统优先（v4.3.0）

> **状态**：建议中  
> **日期**：2026-05-19  
> **决策优先级**：🔴 P0  
> **可逆性**：不可逆（破坏性变更）

---

## 背景

v4.2.0 及之前的架构使用系统级持久化存储 Agent 的任务和事件数据：

- Task JSON：`~/.agentsstate/agent-self-development/tasks/{runId}.json`
- Session：`~/.agentsstate/agent-self-development/sessions.json`
- Memory：`~/.agentsmemory/{agentId}.sqlite`
- Flow：`~/.agentsflows/registry.sqlite`

这种设计的弊端：
1. **Agent 无法跨项目复用上下文**：任务数据绑定到插件系统目录，而非被管理的项目目录
2. **双系统冗余**：项目级 `.agentstasks/{runId}.json`（Agent 写入）与系统级 task 数据（插件写入）维护同构内容
3. **适配器复杂度高**：State / Memory / Flow / Log 四个适配器增加了不必要的抽象层

v4.3.0 的定位是「工具插件」——插件只暴露工具，Agent 在项目目录中自主管理数据。

---

## 决策

**v4.3.0 所有 Agent 可见的任务和事件数据均写入项目级 `./.agents` 目录。**

| 数据类型 | v4.2.0 路径 | v4.3.0 路径 | 写入者 |
|----------|-------------|-------------|--------|
| Task JSON | `~/.agentsstate/.../tasks/{runId}.json` | `./.agentstasks/{runId}.json` | Tool Plugin |
| Event Markdown | `~/.agentsmemory/...`（归档） | `./.agentsevents/{date}/{time}.md` | Tool Plugin |
| Task Archive | `~/.agentsstate/.../archive/` | `./.agentstasks/archive/` | Tool Plugin |

系统级持久化（`~/.agents`）在 v4.3.0 中**完全移除**。如需记忆功能，由 Agent 自行管理或未来版本通过独立 Memory tool 实现。

## 方案

### 对象层 IO 改造

```javascript
// utils/file.js
export async function readJson(filePath) {
  const content = await fs.readFile(filePath, 'utf-8');
  return JSON.parse(content);
}

export async function writeJson(filePath, data) {
  await fs.mkdir(dirname(filePath), { recursive: true });
  const tempPath = `${filePath}.tmp`;
  await fs.writeFile(tempPath, JSON.stringify(data, null, 2), 'utf-8');
  await fs.rename(tempPath, filePath);  // 原子替换
}
```

```javascript
// utils/path.js
export function resolveTaskPath(projectRoot, runId) {
  return join(projectRoot, '.agent', 'tasks', `${runId}.json`);
}

export function resolveEventPath(projectRoot, date, time) {
  return join(projectRoot, '.agent', 'events', date, `${time}.md`);
}
```

```javascript
// objects/TaskObject.js
import { readJson, writeJson } from '../utils/file.js';
import { resolveTaskPath } from '../utils/path.js';

async create(params) {
  const taskPath = resolveTaskPath(this.projectRoot, params.runId);
  await writeJson(taskPath, task);
}
```

### 删除的适配器

- `src/common/adapters/state.js` → 完全移除
- `src/common/adapters/memory.js` → 完全移除
- `src/common/adapters/flow.js` → 完全移除
- `src/common/adapters/log.js` → 完全移除
- `src/common/adapters/hook.js` → 完全移除（HookRegistry 非工具插件职责）
- `src/common/adapters/task.js` → 完全移除

---

## 影响

| 影响面 | 说明 |
|--------|------|
| 数据可见性 | Agent 可直接读取 `./.agentstasks/` 和 `./.agentsevents/`，无需通过工具查询 |
| 跨项目隔离 | 每个项目的任务数据独立，天然隔离 |
| 备份/迁移 | 项目目录打包即可带走全部任务历史 |
| 向后兼容 | 破坏性变更；v4.2.0 的系统级数据不会自动迁移（v4.3.0 作为大版本发布，接受此风险） |
| 测试 | 测试可直接在临时目录中创建项目结构，无需 mock 系统级 adapter |

---

## 替代方案

| 方案 | 说明 | 拒绝原因 |
|------|------|----------|
| A. 保留系统级 adapter | 同时维护项目级和系统级两套存储 | 与「极简工具插件」定位矛盾，冗余未消除 |
| B. 系统级作为缓存 | 项目级为主，系统级为备份 | 增加复杂度，无实际需求 |
| C. 可配置存储位置 | 通过配置选择项目级或系统级 | 过度设计，工具插件应始终与项目绑定 |
