# ADR-015：Hook 注入时机精细化（v4.5.0）

> **ADR 编号**：015  
> **标题**：Hook 注入时机精细化：条件触发 vs 全量触发  
> **状态**：[ARCH_READY]  
> **日期**：2026-05-26  
> **作者**：Architect  
> **关联蓝图**：`docs/roadmap/v4.5.0.md`  
> **关联变更**：src/hooks/condition.js（新增）

---

## 1. 背景

v4.4.0 及之前版本采用 **全量 Hook 注入**：每次 `after_tool_call` 和 `before_prompt_build` 触发时均执行注入逻辑，无条件判断。

全量注入的问题：
- **噪声过大**：Agent 每次调用 `task_create` 都收到提醒，即使它正在正常执行
- **上下文污染**：注入的提醒文本与当前任务无关时，干扰 Agent 决策
- **幂等性缺失**：重复注入同一提醒，导致 Agent 收到重复消息
- **无差别触发**：before_prompt_build 在任何时候都触发，不区分 Agent 是否已有 active task

v4.5.0 的目标是实现 **条件触发精准提醒**：只在有实际需要时注入正确的内容。

---

## 2. 决策

**采用条件触发机制：Hook 注入前增加条件判断，只有满足条件时才执行注入。**

### 2.1 条件判断模块化

将条件判断逻辑封装为 `src/hooks/condition.js`，提供两个导出函数：

```javascript
// src/hooks/condition.js
export function evaluateAfterToolCall(event)   // 判断 after_tool_call 是否注入
export async function evaluateBeforePromptBuild(context)  // 判断 before_prompt_build 是否注入
```

返回值结构：
```javascript
{
  shouldInject: boolean,      // 是否注入
  idempotencyKey: string,     // 幂等键（防重复注入）
  prependContext: string      // 注入的提醒文本
}
```

### 2.2 注入时机矩阵

| # | 触发时机 | 监听工具 | 注入条件 | 注入内容 | IdempotencyKey |
|---|----------|----------|----------|----------|----------------|
| M1 | after_tool_call | `task_create` | 返回成功且含 runId | 制定计划 → 拆解 TODO 提醒 | `agent-self-development:task-created` |
| M2 | after_tool_call | `task_update` | 返回成功且 deviationRecorded=true | 偏差分析 → 归因分析提醒 | `agent-self-development:deviation-detected` |
| M3 | after_tool_call | `event_report` | 返回成功且含 eventFilePath | 六维度平衡性判断提醒 | `agent-self-development:event-generated` |
| M4 | before_prompt_build | — | 无 active task | 创建任务提醒 | `agent-self-development:no-active-task` |

### 2.3 幂等性保证

每个注入使用唯一 `idempotencyKey`，OpenClaw 框架层去重。相同 key 的重复注入自动忽略。

### 2.4 注入内容精简

每个注入的 `prependContext` 是一段结构化提醒文本，包含：
- 当前状态的客观描述
- 具体的下一步行动建议（2-5 条）
- 不包含无关的通用认知指导

## 3. 实现

### 3.1 目录结构

```
src/
├── hooks/
│   └── condition.js    # 条件判断逻辑（新增）
├── tools/
│   └── ...             # 6 个工具 handler
└── index.js           # Hook 注册逻辑
```

### 3.2 条件判断流程

```
after_tool_call 触发
  → evaluateAfterToolCall(event)
      → M1: toolName === 'task_create' && success && runId  → shouldInject
      → M2: toolName === 'task_update' && success && deviationRecorded  → shouldInject
      → M3: toolName === 'event_report' && success && eventFilePath  → shouldInject
      → 其他 → shouldInject = false
  → shouldInject=true → enqueueInjection()

before_prompt_build 触发
  → evaluateBeforePromptBuild(context)
      → 扫描 .agents/tasks/ 目录
      → 有 active task → shouldInject = false
      → 无 active task → shouldInject = true
  → shouldInject=true → enqueueInjection()
```

### 3.3 核心实现

```javascript
// src/hooks/condition.js

export function evaluateAfterToolCall(event) {
  const { toolName, result } = event;

  // 解析 tool call 返回结果
  let parsedResult = result;
  if (result?.content?.[0]?.text) {
    try {
      parsedResult = JSON.parse(result.content[0].text);
    } catch {
      parsedResult = result;
    }
  }

  const isSuccess = parsedResult && !parsedResult.error;

  if (toolName === 'task_create' && isSuccess && parsedResult.runId) {
    return { shouldInject: true, idempotencyKey: 'agent-self-development:task-created', prependContext: REMINDERS.taskCreated };
  }

  if (toolName === 'task_update' && isSuccess && parsedResult.deviationRecorded) {
    return { shouldInject: true, idempotencyKey: 'agent-self-development:deviation-detected', prependContext: REMINDERS.deviationDetected };
  }

  if (toolName === 'event_report' && isSuccess && parsedResult.eventFilePath) {
    return { shouldInject: true, idempotencyKey: 'agent-self-development:event-generated', prependContext: REMINDERS.eventGenerated };
  }

  return { shouldInject: false };
}

export async function evaluateBeforePromptBuild(context) {
  // 扫描 .agents/tasks/ 查找 active/draft/pending_approval 状态
  // 无 active task → 注入创建任务提醒
  // 有 active task → 不注入
}
```

## 4. 与旧版本的差异

| 维度 | v4.4.0（全量注入） | v4.5.0（条件触发） |
|------|------------------|-------------------|
| after_tool_call | 每次调用都注入 | 仅监听 task_create/update + event_report |
| before_prompt_build | 每次都注入 | 仅无 active task 时注入 |
| 幂等性 | 无 | idempotencyKey 去重 |
| 提醒内容 | 通用认知指导 | 精准针对当前状态 |
| 上下文污染 | 严重 | 消除 |

---

## 5. 向后兼容性

- 工具接口（task.* / event.*）无变更
- 文件格式（task.json / event.md）无变更
- 仅影响 Hook 注入行为，不影响核心工具功能
- M4（无任务提醒）对多任务并行场景有改善：某个任务完成但不归档时，不会重复提醒

---

## 6. 未来扩展方向

| 方向 | 说明 |
|------|------|
| 更多注入时机 | 如 task_archive 归档后注入「事件复盘」提醒 |
| 动态提醒内容 | 根据任务类型（code/review/doc）生成不同提醒 |
| 提醒频率限制 | 同类型提醒在 N 小时内不重复注入 |
| 注入内容模板化 | 提醒内容从外部模板读取，支持 Agent 自定义 |
