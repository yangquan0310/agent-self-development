# ADR-014: 扁平化工具插件架构

> **ADR 编号**：014  
> **标题**：放弃对象层封装，采用 Handler 直接 IO 的扁平架构  
> **状态**：[ARCH_READY]  
> **日期**：2026-05-19  
> **作者**：Architect  
> **关联蓝图**：`docs/roadmap/v4.3.0.md` v2.0.0  
> **关联事件**：`.agentssessions/2026-05-19/pm-to-architect-blueprint-released-v4.3.0.md`

---

## 1. 背景

v4.2.0 遗留架构在 v4.3.0 转型过程中经历了多次修补（TaskObject 9 方法、EventObject 3 方法、复杂依赖注入、状态机类），但核心问题始终未解决：**一个工具插件不应该有"对象层"**。

PM 蓝图 v2.0.0 解除了所有架构限制，Architect 获得完整设计授权。本 ADR 记录彻底放弃旧架构影响、重新设计为扁平化工具插件的决策。

---

## 2. 决策

**采用扁平化架构：Tool Handler 直接读写文件，不引入任何中间对象层。**

### 2.1 删除的抽象

| 旧抽象 | 删除原因 |
|--------|---------|
| `TaskObject` 类（含依赖注入） | 不封装为类，改为 `objects/task.js` 纯函数模块 |
| `EventObject` 类（含依赖注入） | 同上，改为 `objects/event.js` 纯函数模块 |
| 依赖注入（deps.state / deps.log / deps.caseIndex） | 业务函数直接调用 `utils/io.js`，无注入 |
| `deviate()` / `attribute()` 独立方法 | 内聚到 `task.update` 的参数中 |
| `setOutcome()` / `linkEvent()` 独立方法 | 同上，内聚到 `task.update` |
| `generate(runId, task)` 双参数 | `event.report(runId)` 内部自己读 task.json |

### 2.2 保留的抽象

| 抽象 | 保留原因 |
|------|---------|
| `utils/io.js` — `readJson` / `writeJson` / `ensureDir` / `moveFile` | 文件 IO 的原子性和错误处理需要复用 |
| `utils/resolve.js` — `taskPath` / `eventPath` / `archivePath` | 路径规则需要集中管理 |
| `templates/task.json` / `templates/event.md` | 数据结构模板和渲染模板 |

## 3. 新架构

```
src/
├── index.js              # 入口：加载模板，注册工具
├── tools/
│   ├── index.js          # 遍历注册
│   ├── schemas.js        # 6 个工具的 JSON Schema
│   ├── handlers.js       # 6 个 handler 函数（直接操作文件）
│   └── adapter.js        # adaptReturn / adaptError
├── templates/
│   ├── task.json         # 任务数据结构模板
│   └── event.md          # 事件报告 Markdown 模板
└── utils/
    ├── io.js             # 文件 IO 原子操作
    └── resolve.js        # 路径解析
```

### 3.1 数据流

```
Agent 调用 tool
  → Tool Handler（参数校验 + 调用 objects/ 函数）
  → objects/task.js 或 objects/event.js（业务逻辑 + 文件 IO）
  → utils/io.js（原子读写）
  → 返回 { content: [{ type: 'text', text: JSON.stringify(result) }] }
```

业务逻辑在 `objects/` 中，Handler 层负责参数解包和返回值适配。

### 3.2 6 个工具

| 工具名 | Handler 调用 | objects/ 函数 | 文件操作 |
|--------|-------------|---------------|---------|
| `task.create` | `handlers.create` | `objects/task.create` | 写 `.agentstasks/{runId}.json` |
| `task.update` | `handlers.update` | `objects/task.update` | 读 → 改 → 写 task.json |
| `task.advance` | `handlers.advance` | `objects/task.advance` | 读 → 改 phase → 写 |
| `task.get` | `handlers.get` | `objects/task.get` | 读 task.json（双路径） |
| `task.archive` | `handlers.archive` | `objects/task.archive` | 移动 → archive/ |
| `event.report` | `handlers.report` | `objects/event.report` | 读 task.json → 渲染 → 写 event.md |

### 3.3 task.json 结构

```json
{
  "runId": "",
  "status": "draft",
  "taskType": "",
  "createdAt": 0,
  "updatedAt": 0,
  "plan": {
    "prompt": "",
    "context": { "goal", "constraints", "successCriteria" },
    "workspace": { "artifacts", "tools", "skills" },
    "execution": { "phases": [...], "currentPhase": 0 }
  },
  "deviations": [],
  "attributions": [],
  "outcome": {},
  "eventFilePath": ""
}
```

### 3.4 Handler 示例

```javascript
// objects/task.js
import { readJson, writeJson, ensureDir, moveFile } from '../utils/io.js';
import { taskPath, archiveTaskPath } from '../utils/resolve.js';

export async function create(params, context) {
  const { runId } = params;
  if (await readJson(taskPath(runId))) {
    return { error: `task 已存在: ${runId}` };
  }
  const task = renderTemplate(context.templates.task, params);
  await writeJson(taskPath(runId), task);
  return { task };
}

export async function update(params, context) {
  const task = await readJson(taskPath(params.runId))
    || await readJson(archiveTaskPath(params.runId));
  if (!task) return { error: `task 不存在` };

  if (params.status) { /* 状态机校验 */ task.status = params.status; }
  if (params.deviation) { /* 追加偏差 */ }
  if (params.attribution) { /* 追加归因 */ }
  if (params.outcome) { task.outcome = { ...task.outcome, ...params.outcome }; }
  if (params.eventFilePath) { task.eventFilePath = params.eventFilePath; }

  task.updatedAt = Date.now();
  await writeJson(taskPath(params.runId), task);
  return { task };
}
```

```javascript
// tools/handlers.js
import * as task from '../objects/task.js';
import * as event from '../objects/event.js';

export async function create(params, context) {
  const result = await task.create(params, context);
  return adaptReturn(result);
}
```

## 4. 与旧架构的差异

| 维度 | 旧架构（对象层） | 新架构（扁平化） |
|------|----------------|----------------|
| 抽象层级 | 3 层：Tool → Object → IO | 2 层：Tool → IO |
| 代码量 | TaskObject 700+ 行 + EventObject 400+ 行 | handlers.js ~300 行 |
| 测试复杂度 | 需 mock Object 依赖 | 直接 mock `utils/io.js` |
| 心智负担 | 需理解 Object 生命周期 | 直接理解文件读写 |
| 灵活性 | Object 接口冻结后难以调整 | Handler 可随时增减字段 |

## 5. 保留的 PM 需求验证

| PM 需求 | 实现方式 |
|---------|---------|
| 任务管理工具 | `task.create/update/advance/get/archive` 直接读写 `.agentstasks/` |
| 事件报告工具 | `event.report` 读取 task.json → 渲染模板 → 写 `.agentsevents/` |
| 不暴露认知指导 | 无 planning/monitoring/regulation/development 工具 |
| 不注入 Hook | 纯 `api.registerTool`，无 prompt 修改 |
| 保留文件格式契约 | `.agentstasks/{runId}.json` + `.agentsevents/{date}/{runId}.md` |
| event.md 延迟凝练 | `event.report` 仅在 task.completed 时调用，一次性渲染 |
