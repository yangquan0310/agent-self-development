## 1. 案例概述

这是一个**人机协同多Agent分工**的完整协作实践，涉及 4 个 Agent 角色协作完成学生论文修改任务。该案例验证了 v4.0.0「项目上下文层」和「多Agent协作体系」的可行性。

| 属性 | 值 |
|------|-----|
| **项目类型** | 学术写作协作 |
| **Agent 数量** | 4（psychologist, writer, reviewer, steward） |
| **协作模式** | 流水线分工 + 审核闭环 |
| **项目路径** | `/root/实验室仓库/学生论文修改/` |

---

## 2. 角色与职责

### 2.1 角色分工表

| 角色 | Agent ID | 职责范围 | 核心能力 | 交付物 |
|------|----------|----------|----------|--------|
| **心理专家** | psychologist | 文献综述 + 讨论初稿 | 心理学专业知识、文献检索、APA格式 | 新增32篇参考文献、讨论章节扩展 |
| **写作专家** | writer | 整合全文 + 变量修正 + 修改报告 | 学术写作、格式规范、跨章节一致性 | 论文_R1.md、修改报告.md |
| **审稿助手** | reviewer | 全文审核 + 审稿意见 | 质量检查、数据审核、格式审查 | 审稿意见.md（8项审核结果） |
| **大管家** | steward | 文件归档 + 版本管理 | 文件管理、版本控制、交付管理 | 归档文件、README更新 |

### 2.2 能力边界

- **psychologist**：擅长文献综述和理论分析，不擅长全文格式整合
- **writer**：擅长写作规范和一致性检查，不擅长心理学专业内容创作
- **reviewer**：擅长质量审核，不直接修改内容
- **steward**：擅长文件管理，不直接参与内容创作

## 3. 协作流程

### 3.1 流程总览

```
用户
  │
  ▼ 分配任务
┌─────────────────┐
│  psychologist  │ ← 擅长文献综述
│  · 文献综述 A1  │
│  · 讨论 B1/B2  │
│  · 参考文献32篇 │
└─────────────────┘
  │
  ▼ 举手请求
┌─────────────────┐
│     writer     │ ← 擅长全文整合
│  · Fix-R1~R5   │
│  · 变量清理    │
│  · 审稿意见修正│
└─────────────────┘
  │
  ▼ 交付审核
┌─────────────────┐
│    reviewer    │ ← 擅长质量审核
│  · 8项审核清单 │
│  · 发现3处🔴   │
└─────────────────┘
  │
  ▼ 返回修正（或通过）
┌─────────────────┐
│     steward    │ ← 擅长文件管理
│  · 归档文件    │
│  · 版本记录    │
└─────────────────┘
```

### 3.2 详细阶段

#### 阶段1：任务分配（用户协调）
1. 用户将论文修改任务分配给 **psychologist**（擅长文献综述与讨论）
2. psychologist 完成：
   - A1. 2.2节：领悟社会支持与大学生社会排斥的关系
   - A2. 2.3节：愤怒反刍的中介作用
   - A3. 2.1.2 概念界定补充引文
   - B1. 5.2节讨论扩展
   - B2. 5.3节讨论扩展
   - C. 新增32篇参考文献（APA 7th）
3. psychologist 在 **TODO.md** 标记任务完成，向用户汇报

#### 阶段2：举手请求协作
- psychologist 发现需要 **writer** 整合全文
- 在 TODO.md「待分配」写入子任务：
  > 「我擅长文献综述，但全文整合和变量清理需要写作专家。建议分配给 writer。」
- 用户收到后，将子任务分配给 writer
- **关键点**：psychologist 先完成自己擅长部分，再举手，不阻塞执行

#### 阶段3：writer 执行（含多轮修正）

| 修正轮次 | 内容 | 产出 |
|----------|------|------|
| Fix-R1 | 结果部分变量混淆清理 | 论文_R1.md 部分更新 |
| Fix-R2 | 跨章节变量混淆清理 | 论文_R1.md 部分更新 |
| Fix-R3 | 文献综述与讨论整合 | 删除"网络欺凌"残留、修正中介变量描述 |
| Fix-R5 | 审稿意见修正（6项） | 修正β值、删除多余文献、统一括号格式 |
| Fix-R6 | 导出论文全文 MD（待完成） | 单一 Markdown 文件 |

- 每轮修正后更新 **TODO.md**，标记进度
- writer 产出：
  - `manuscripts/领悟社会支持对大学生社会排斥的影响：愤怒反刍的中介作用_R1.md`（42989 bytes）
  - `文档/修改报告.md`（7969 bytes）

#### 阶段4：reviewer 审核

**审核清单（8项）**：

| # | 审核项 | 结果 | 发现问题 |
|---|--------|------|----------|
| 1 | 变量一致性 | ✅ | 无"网络欺凌"残留 |
| 2 | 方向性 | ⚠️ | β值舍入误差（0.55 vs 0.56）|
| 3 | 假设-数据-结论一致性 | ✅ | — |
| 4 | 摘要一致性 | ✅ | — |
| 5 | 文献引用 | 🔴 | 9篇参考文献正文未引用 |
| 6 | 表格数据 | 🔴 | 表4.4与正文β值不一致 |
| 7 | 逻辑连贯性 | 🔴 | 结论提及"学历"变量（全文无此分析）+ H1表述错误 |
| 8 | 格式规范 | 🟡 | 中英文括号混用 |

**产出**：`文档/审稿意见.md`（10382 bytes）

**流转**：发现 🔴 问题 → **返回 writer 修正** → 修正后重新审核

#### 阶段5：steward 归档

**接收交付物**：
- ✅ 论文_R1.md（42989 bytes）
- ✅ 修改报告.md（7969 bytes）
- ✅ 审稿意见.md（10382 bytes）

**归档操作**：
- 终稿 → `manuscripts/`
- 修改报告 → `文档/修改报告_R1.md`
- 审稿意见 → `文档/审稿意见.md`
- 原始版 → `临时数据/草稿/领悟社会支持.0/论文原始版.md`
- 更新 README.md 版本记录（v1 → v2）
- 备份原始版：`uploads/原始版.docx` 保留

**待完成**：云文档上传

## 4. 关键协作机制

### 4.1 TODO.md 进度看板

**状态列**：
- **待办**：任务已定义，尚未启动
- **进行中**：Agent 正在执行
- **待分配**：需要其他 Agent 能力，等待用户协调
- **待确认**：等待用户确认
- **已完成**：成果归档

**任务格式**：
```markdown
- [ ] 任务名 — @agent-id — HH:MM开始 — 来源：用户分配
```

**流转规则**：
1. 完成者移到「待确认」
2. 用户 [APPROVED] → 移到「已完成」
3. 用户 [REJECTED] → 回到「进行中」

### 4.2 文件系统协作

| 目录 | 职责 | 该案例中的使用 |
|------|------|--------------|
| **manuscripts/** | Agent 工作草稿 | writer 产出论文_R1.md |
| **docs/** | 定稿（待实现） | 用户确认后应移入（当前未执行） |
| **knowledge/** | 项目知识 | 心理学家文献综述产出 |
| **临时数据/** | 归档草稿 | 原始版论文归档 |
| **uploads/** | 用户上传原始材料 | 原始版.docx |

### 4.3 举手请求协议

**触发条件**：Agent 发现需要其他 Agent 能力时

**操作步骤**：
1. 在 TODO.md「待分配」写入子任务：
   ```markdown
   ## 待分配（用户协调）
   - [ ] 子任务：{描述} — 需要擅长{能力}的 Agent — 举手者：@{agent-id}
   ```
2. 向用户汇报：
   > 「我擅长{我的能力}，但发现需要{其他能力}。建议分配此子任务给擅长{其他能力}的 Agent。我继续处理{我的部分}。」
3. 用户协调后分配新 Agent

### 4.4 审核闭环机制

**审核结果标记**：
- 🔴 **必须修改**：影响论文正确性的问题
- 🟡 **建议修改**：格式或表述优化
- 🟢 **可优化**：非必须改进

**流转规则**：
- 发现 🔴 → **返回原 Agent 修正**
- 修正后重新审核
- 无 🔴 → 交付 steward 归档

## 6. 经验总结

### 6.1 成功要素

1. **明确的角色分工**
   - 每个 Agent 有清晰的能力边界（心理学家不做格式整合，writer 不做文献创作）
   - 避免能力重叠导致的冲突

2. **TODO.md 驱动**
   - 所有 Agent 通过同一进度看板了解全局状态
   - 用户通过 TODO.md 快速掌握项目进度

3. **审核闭环**
   - reviewer 的 8 项审核清单确保质量
   - 「审核 → 修正 → 再审」闭环不可或缺

4. **举手不阻塞**
   - psychologist 发现需 writer 时，先完成自己部分再举手
   - 避免空等，提高并行效率

### 6.2 可改进点（v4.0.0 解决方向）

| 序号 | 实践痛点 | 当前状态 | v4.0.0 改进 |
|------|----------|----------|-------------|
| 1 | 缺少 `.openclaw/` 元数据层 | 无 events/、tasks/、locks/ | P0：创建结构化记录 |
| 2 | 审核发现问题后手动返回 | reviewer 发现后需手动通知 writer | P1：状态机自动流转 |
| 3 | steward 手动移动文件归档 | 人工移动文件 | P0：文件移动协议自动化 |
| 4 | 无冲突检测 | 若多 Agent 同时编辑同一文件无预警 | P0：`.openclaw/locks/` 锁机制 |
| 5 | 缺少修改报告模板 | writer 自行编写报告格式 | P1：SKILL.md 项目级模板 |
| 6 | 无事件文件记录 | 每次对话的偏差、归因无结构化记录 | P0：`.openclaw/events/` 事件日志 |

### 6.3 对 v4.0.0 的启示

1. **验证了「文件系统协作」的可行性**：
   - psychologist → writer → reviewer 全程通过文件系统传递成果
   - 无 `sessions_send` 直接对话，符合 v4.0.0 设计原则

2. **验证了「举手请求」的有效性**：
   - 不阻塞的举手机制使流水线效率最大化
   - 用户作为协调者的角色不可或缺

3. **暴露了「自动化流转」的需求**：
   - 当前审核发现问题后需手动返回，v4.0.0 状态机可解决
   - 文件归档需手动移动，v4.0.0 文件移动协议可自动化

4. **证明了「审核清单」的必要性**：
   - reviewer 的 8 项审核发现 3 处 🔴 问题
   - 若无审核闭环，问题将流入最终交付物

## 7. 复用指南

### 7.1 如何复用该模式

**适用场景**：
- 学术写作协作（论文、报告、综述）
- 多阶段内容创作（创作 → 整合 → 审核 → 归档）
- 需要专业分工的复杂任务

**初始化步骤**：
1. 创建项目目录，复制四文件契约模板
2. 在 metadata.json 定义参与 Agent 及其能力
3. 在 TODO.md 创建初始任务列表
4. 按流水线分配任务给各 Agent

**关键配置**：
```json
// metadata.json 示例
{
  "project": {
    "name": "学生论文修改",
    "type": "academic-writing",
    "version": "1.0.0"
  },
  "agents": [
    {"id": "psychologist", "role": "content-expert", "capabilities": ["文献综述", "理论分析"]},
    {"id": "writer", "role": "integrator", "capabilities": ["写作规范", "格式整合"]},
    {"id": "reviewer", "role": "auditor", "capabilities": ["质量审核", "数据检查"]},
    {"id": "steward", "role": "archivist", "capabilities": ["文件管理", "版本控制"]}
  ],
  "collaboration": {
    "mode": "human-agent",
    "context_source": "file-system"
  }
}
```

### 7.2 审核清单模板

```markdown
## reviewer 审核清单

| # | 审核项 | 检查内容 | 通过标准 |
|---|--------|----------|----------|
| 1 | 变量一致性 | 全文变量名称一致 | 无残留旧变量名 |
| 2 | 方向性 | "正向/负向预测"与数据一致 | β值符号与表述一致 |
| 3 | 假设-数据-结论一致性 | H1/H2/H3 与结果、结论对应 | 无矛盾 |
| 4 | 摘要一致性 | 中英文摘要数据一致 | 数据匹配 |
| 5 | 文献引用 | 正文引用与参考文献一一对应 | 无未引用文献 |
| 6 | 表格数据 | 表格数据与正文一致 | 数值匹配 |
| 7 | 逻辑连贯性 | 绪论→文献→假设→方法→结果→讨论→结论 | 逻辑链条完整 |
| 8 | 格式规范 | APA 7th、括号格式、字体 | 符合规范 |
```
