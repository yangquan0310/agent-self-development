## 五、❌ 重命名过程中误伤的代码样例

**重命名机械替换误改了 4 处 JavaScript 代码样例**（位于 markdown 文档的代码块中）。

这些代码块演示的是 `tools/handlers.js` 中使用 `import * as task from '../objects/task.js'` 命名空间导入后的实际调用方式——必须使用**点分**形式（`task.create(`、`event.report(`、`task.update(`），**不应**改成下划线形式（`task_create(`、`event_report(`、`task_update(`）。

> 注：任务规范 2.1 明确要求 `src/tools/handlers.js` 保留点分调用。本报告将此规范扩展到"出现在代码块中、且语义为命名空间方法调用"的场景——这些位置的误改与 src/ 层是同类问题（虽然位于文档中，但代码可读性受影响）。

| 文件 | 行 | 现状 | 应为 |
|------|----|------|------|
| `docs/CONVENTIONS.md` | 91 | `await task_create(params, context);` | `await task.create(params, context);` |
| `docs/adr/adr-014.md` | 149 | `await task_create(params, context);` | `await task.create(params, context);` |
| `docs/specs/tool-registry-interface.md` | 227 | `await event_report(params, context);` | `await event.report(params, context);` |
| `docs/specs/tool-registry-interface.md` | 231 | `await task_update(` | `await task.update(` |

**修复建议**（非阻塞，可在 v4.5.1 发布前修复）：

```diff
# docs/CONVENTIONS.md:91
 export async function create(params, context) {
-  const result = await task_create(params, context);
+  const result = await task.create(params, context);
   return adaptReturn(result);
 }

# docs/adr/adr-014.md:149
 export async function create(params, context) {
-  const result = await task_create(params, context);
+  const result = await task.create(params, context);
   return adaptReturn(result);
 }

# docs/specs/tool-registry-interface.md:227,231
 export async function report(params, context) {
-  const result = await event_report(params, context);
+  const result = await event.report(params, context);
   ...
-  await task_update(
+  await task.update(
     { runId: params.runId, eventFilePath: result.eventFilePath },
     context
   );
```

**未发现** 其他类型的误伤（如 `'task.create'` 工具名被改成 `'task.create'` 之外的形式）。
