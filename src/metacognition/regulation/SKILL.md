# Regulation — 归因分析与 Event 记录

> 元认知子模块 - 调节阶段
> 在 Monitoring 标记偏差后，分析根因、制定调节方案、记录到事件文件
> **先归因分析，再追加到事件文件；重大偏差需请示用户**

---

## 注入上下文

本 skill 在 **`before_prompt_build`** 时**条件注入**。触发条件：

**当前任务的事件文件中存在「偏差」章节但无「归因」章节**

即：Agent 已在事件文件中记录了偏差，但尚未完成归因分析。

**注入内容**：
- regulation skill 文本（本文档）
- 事件文件中的偏差摘要（`type`、`description`）

---

## 核心原则：事件文件驱动

v4.0.0 中偏差和归因从 `task.deviations` / `task.attributions` 迁移到**事件文件**（`.openclaw/events/{YYYY-MM-DD}/{HH-MM-SS}.md`）。

**数据流向**：
1. Agent 发现偏差 → 在事件文件中追加「偏差」章节
2. 插件扫描事件文件 → 检测到未处理偏差 → 注入 regulation skill
3. Agent 完成归因 → 在事件文件中追加「归因」章节
4. 插件检测到「归因」章节存在 → 视为偏差已处理

---

## Agent 职责

### 职责 A：归因分析

**触发条件**：收到 regulation skill 注入（即事件文件中有未处理偏差）

**你需要做的**（决策层）：

1. **读取事件文件中的偏差**
   - 打开当前任务的事件文件（`.openclaw/events/{YYYY-MM-DD}/{HH-MM-SS}.md`）
   - 阅读「偏差」章节内容
   - 了解偏差类型（`type`）、描述（`description`）、影响范围

2. **根因分析**
   - **计划问题**：Plan 制定不合理？阶段划分有误？
   - **执行问题**：Agent 偏离了 Plan？工具使用错误？
   - **外部因素**：用户需求变化？资源不足？环境异常？
   - **上下文问题**：未读取历史文件？重复劳动？（v4.0.0 新增）

3. **制定调节方案**

   | 方案 | 适用场景 | 操作 |
   |------|---------|------|
   | **A. 调整 Plan** | 计划本身不合理 | 增删改 phases、回到 pending_approval 重新汇报 |
   | **B. 调整执行** | 执行偏离但计划合理 | 修正当前输出方向、重新执行当前阶段 |
   | **C. 请求用户介入** | critical 级别或需求变更 | 向用户汇报偏差和根因，提供选项，等待决策 |

4. **在事件文件中追加「归因」章节**
   ```markdown
   ## 6. 归因（Attribution）

   - 根本原因：{分析结果}
   - 影响评估：{影响范围}
   - 策略更新：{后续调整建议}
   ```

**处理完成标志**：事件文件中存在「归因」章节 → 视为已处理

---

### 职责 B：执行调节

**触发条件**：归因分析已完成

**你需要做的**（决策层）：

1. **执行调节方案**
   - 若方案 A（调整 Plan）：修改 Plan 后向用户汇报（如为 major/critical），获得确认后通知插件更新
   - 若方案 B（调整执行）：修正当前输出，重新推进当前阶段
   - 若方案 C（用户介入）：向用户清晰呈现偏差、根因、选项，等待决策

2. **更新事件文件「结果」章节**（任务最终完成时）
   ```markdown
   ## 7. 结果（Outcome）

   - 最终状态：{完成 / 修正 / 放弃}
   - 调节效果：{方案执行后的结果}
   ```

---

## 决策检查点

在 regulation 阶段结束时，请确认：

- [ ] 事件文件中的偏差是否已完整阅读？
- [ ] 根因是否已明确区分"计划问题"和"执行问题"？
- [ ] 调节方案是否已权衡成本、风险和收益？
- [ ] 若为 major/critical 级别，是否已向用户汇报并获得确认？
- [ ] 事件文件中是否已追加「归因」章节？
- [ ] 如有 Plan 调整，是否已同步更新事件文件？

## 状态流转

```
Agent 输出 [STATUS: revising] [REASON: xxx]
    ↓ 插件更新 task.status = 'revising'
Agent 在事件文件中追加「偏差」章节
    ↓
下次 before_prompt_build 插件扫描事件文件
    ↓ 检测到未处理偏差 → 注入 regulation skill
Agent 完成根因分析
    ↓
Agent 在事件文件中追加「归因」章节
    ↓ 插件检测到「归因」存在 → 视为已处理
Agent 执行调节方案
    ↓
返回 monitoring 继续追踪 / 或返回 Planning 重新汇报
```

## 与其他 Skill 的关系

| Skill | 注入时机 | 职责边界 |
|-------|---------|---------|
| `planning` | `before_prompt_build` | 提供 Plan 基准，调节后可能需要回到 planning 重新汇报 |
| `monitoring` | `before_prompt_build`（task=active）| 负责提供目标和历史偏差，Agent 自主标记偏差 |
| `regulation` | `before_prompt_build`（条件注入）| 负责分析事件文件中的未处理偏差，追加归因章节 |
| `development` | `before_prompt_build`（task=completed）| 任务完成后基于事件文件分析同化/顺应 |
