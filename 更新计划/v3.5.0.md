## 问题诊断

### 当前 v3.4.1 实现中存在三类问题：

**第一类：Hooks 使用不合规（违反官方文档）**

1. `Metacognition.onLlmOutput` 返回 `prependSystemContext` 注入 monitoring skill
   - 官方文档：`llm_output` 是**观察型**钩子（非粗体），"观察提供商输出"
   - 当前实现：llm_output 中检测 [NEED_PLAN] 后返回 `prependSystemContext` 注入 monitoring
   - 影响：功能上可能工作，但文档层面不合规，未来版本可能失效

2. `WorkingMemory.onAgentEnd` 返回 `prependSystemContext` 注入 working_memory skill
   - 官方文档：`agent_end` 是**观察型**钩子，"观察最终消息、成功状态和运行时长"
   - 当前实现：agent_end 归档后返回 skill 注入
   - 影响：agent_end 后 Agent 不再生成输出，注入无意义；且文档不合规

3. `Personality.onAgentEnd` 返回 `prependSystemContext` 注入 development skill
   - 同上，agent_end 为观察型钩子，不应返回注入

**第二类：运行时功能不工作（测试验证失败）**

4. 插件 hooks 在 webchat 会话中未触发日志记录
   - 现象：`main.log` 始终为空，无自动写入记录
   - 子现象：task 未创建、session 未追踪、state 无变化
   - 待排查：是 llm_output 事件格式不匹配，还是 hooks 在当前通道中根本未触发

5. `plan.js` `crypto.randomUUID()` 未导入 `crypto` 模块
   - ESM 环境下抛出 `ReferenceError: crypto is not defined`
   - 影响：通过 Plan.createPlan() 创建 task 时会崩溃

**第三类：代码质量问题**

6. `state.js` `_cleanupOldArchives` 硬编码 `MAX_ARCHIVED_TASKS`（50），忽略配置项 `this.maxArchivedTasks`
7. `Flow.getByRunId` / `getByPhase` 全表扫描 SQLite，无索引
8. `Memory._getDb` 长期持有数据库连接不关闭
9. `session.js` `createSession` sessionId 格式 `session:${taskFamily}:${taskFamily}` 语义重复
10. `event.js` Event 类未在业务逻辑中使用，为冗余代码
11. `index.js` 存在未使用的 `dirname` import 和未使用的 `task`/`flow`/`memory`/`hook` 实例

- [ ] **评估 `llm_output` 中的 `[NEED_PLAN]` 检测与注入**

  - **功能上这是同一次回复闭环的关键，但文档层面不合规**

    - **方案 B**：使用 `before_prompt_build`（多一轮交互）
      - `llm_output` 仅检测标记、创建 task（draft），**不返回任何注入**
      - 下一轮 `before_prompt_build` 检测到 task=draft → 注入 planning skill
      - Agent 在下一轮制定 Plan（用户会看到 NEED_PLAN 标记后多一轮回复）

## 新 Hooks 注入映射（修正后）

### 主任务流

```
用户提问
    │
    ▼
before_prompt_build
    │
    ├── 无 task ────────────────────────────────────────────┐
    │                                                      ▼
    │                                            注入 planning skill（评估阶段）
    │                                            或 assessment skill（如需）
    │                                                      │
    │                                            Agent 评估 → 简单任务：直接回答
    │                                            Agent 评估 → 复杂任务：输出 [NEED_PLAN]
    │                                                      │
    │                                            llm_output 检测到 [NEED_PLAN] 标记
    │                                            （仅观察，不返回注入）
    │                                                      │
    │                                            创建 task（draft）
    │                                                      │
    │                                            before_agent_finalize
    │                                            检测到 NEED_PLAN → action: "revise"
    │                                            追加 planning skill + instruction
    │                                                      │
    │                                            Agent 制定 Plan（同一次回复的修订传递）
    │                                                      │
    │                                            向用户汇报 Plan（status: pending_approval）
    │                                                      │
    ├── task=draft ──→ 注入 planning skill → 修改 Plan → 等待用户确认
    │
    ├── task=active ─→ 注入 monitoring skill + 执行上下文 → Agent 执行阶段
    │                                                      │
    │                                            阶段完成 / 用户终止
    │                                                      │
    │                                                      ▼
    │                                            agent_end（即发即弃，30s 超时）
    │                                                      │
    │                                            ├─ WorkingMemory：task 归档到 archive/
    │                                            ├─ Events：聚合 deviations/attributions 到 Memory
    │                                            ├─ Personality：记录 completed 日志（不注入 skill）
    │                                            └─ Metacognition：清理流式缓冲、_injectCount
    │
    └── 无 task 但有历史经验 ──→ 可选注入 development skill 提示（Agent 自行回顾人格文件）
```

**说明**：
- **development skill（人格回顾）** 不在 `agent_end` 注入（文档不合规且 agent_end 后无新输出），改为：
  - `agent_end` 仅记录 completed 日志
  - 下一次 `before_prompt_build`（无 task）时，若检测到近期有 completed 的同类型 task，可选注入 development skill 提示
  - 或 Agent 自行读取 `MEMORY.md` 中的人格维度，自主决定更新时机
- **简单任务**（查询、翻译、计算）不创建 task，不触发后续 agent_end 归档逻辑

## 关键设计决策

### 为什么 monitoring skill 要从 llm_output 迁移到 before_prompt_build？
- 官方文档明确 `llm_output` 为观察型钩子，不应返回系统上下文
- `before_prompt_build` 是设计用于"在模型调用前添加动态上下文"的钩子
- monitoring 指导 Agent 在生成回复前检查 Plan 一致性，时机上更符合 before_prompt_build

### 为什么 personality skill 要从 agent_end 移除？
- 官方文档明确 `agent_end` 为观察型钩子，"即发即弃"，30秒超时
- agent_end 后 Agent 不再生成输出，返回 `prependSystemContext` 无意义
- 人格更新应在 Agent 开始新回合时（before_prompt_build）注入 development skill，让 Agent 在制定新 Plan 前回顾上一次经验

### llm_output 中的 NEED_PLAN 检测 + planning skill 注入是否保留？
- **保留**。虽然 llm_output 文档分类为观察型，但功能上这是唯一能在 Agent 同一次回复中追加 skill 的方式
- 这是 "Agent 输出标记 → 插件检测 → 插件追加 skill → Agent 继续回复" 闭环的关键
- 添加明确注释，标记为依赖 OpenClaw 实现细节，后续版本关注兼容性

### llm_output 中的 NEED_PLAN 机制（重要变更）

**官方约束**：`llm_output` 为**仅用于观察**的钩子，不应返回系统上下文注入。

当前 v3.4.1 实现的问题：
```javascript
// 不合规：llm_output 返回 prependSystemContext
async onLlmOutput(event, ctx) {
  // ... 检测 NEED_PLAN ...
  return { prependSystemContext: planningSkill }; // ❌ 不应在 llm_output 中返回
}
```

**v3.5.0 修正方案**：
1. `llm_output` 仅检测 `[NEED_PLAN]` 标记 + 创建 task（draft），**不返回任何注入**
2. `before_agent_finalize` 拦截最终答案，检测到 NEED_PLAN 时请求修订：
   ```javascript
   return {
     action: "revise",
     reason: "检测到 NEED_PLAN 标记，需要制定 Plan",
     retry: {
       instruction: "请根据 planning skill 制定完整 Plan",
       maxAttempts: 2
     }
   };
   ```
3. Harness 追加 planning skill 到上下文，执行第二次模型传递
4. Agent 在修订传递中制定 Plan（用户视觉上为同一条回复）

**备选方案**：若 `before_agent_finalize` 不适用，则 `llm_output` 仅创建 task，planning skill 在下一轮 `before_prompt_build`（task=draft）中注入。
