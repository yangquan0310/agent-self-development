# v3.6.0 更新计划：项目文档系统

> 基于 v3.5.0 → v3.5.1 的代码演进与文档现状审计
> 解决"文档与代码不同步""README 过度膨胀""缺少自动化校验"三大痛点

---

## 设计目标

1. **文档与代码同步**：消除 `_meta.json` 幽灵引用、修正 skill frontmatter 过时信息
2. **文档分层解耦**：README 瘦身 → 用户文档；AGENTS.md 聚焦 → 开发指南；新增 `src/docs/` → 架构文档
3. **自动化校验**：新增 `scripts/validate-docs.js`，CI 中自动检测 frontmatter 与实际代码的偏差
4. **统一导航**：新增 `src/docs/INDEX.md`，所有 skill 文档的依赖关系图与快速入口
5. **版本溯源**：更新计划与代码变更建立关联，新增 CHANGELOG.md

## 关键设计决策

### 为什么保留 `working-memory/SKILL.md` 作为参考文档？
- v3.5.0 的核心变更之一是 `agent_end` 纯观察化，彻底移除了所有 skill 注入
- `working_memory` skill 的唯一自动注入时机就是 `agent_end`，该时机已不存在
- 但 `session.js` 仅包含 `createSession` / `releaseSession` / `destroySession` 基础方法，**未覆盖**复用策略、决策检查点等策略性知识
- 直接删除会导致 Agent 在 planning 阶段缺少 Session 管理指导
- 因此改为参考文档（`injected_at: reference_only`），并将核心复用规则迁移到 `planning/SKILL.md`

### 为什么将技术细节从 README 迁移到 `src/docs/`？
- README 的首要读者是**潜在用户**（决定是否安装、如何配置）
- 详细的架构设计、类图、Hook 映射表是**开发者**和**运行时 Agent** 需要的
- 分层后：README → "这是什么、怎么装"；AGENTS.md → "怎么改代码"；src/docs/ → "技术细节参考"
- 符合开源项目的文档最佳实践（README 精简 + docs/ 详细）

### 为什么 frontmatter 需要 `injected_when`？
- v3.5.0 中同一钩子（`before_prompt_build`）在不同条件下注入不同 skill
- 仅写 `injected_at: before_prompt_build` 不足以让 Agent 理解触发条件
- `injected_when: task.status === 'active'` 明确告知 Agent："只有在这个状态下你才会看到我"

### 为什么校验脚本要扫描 `module.js` 的 `gateway.on` 注册？
- 文档与代码不同步的根源是"改了代码忘了改文档"
- 人工检查不可靠，必须自动化
- 扫描实际注册代码是最可靠的校验源（相比手动维护的白名单）
