# If-Then 规则编写指南

> 本文档指导代理如何正确编写 If-Then 规则。详细标准见 [if-then-rule-standard.md](if-then-rule-standard.md)。

---

## 快速判断

| 问题 | 答案 | 说明 |
|------|------|------|
| 能用三句话说清楚吗？ | 不能 | 不进 If-Then |
| 是跨工具组合吗？ | 是 | ✓ 可进 |
| 容易误操作吗？ | 是 | ✓ 可进 |
| 是单个工具的基础用法吗？ | 是 | 不进 If-Then |
| 是无条件绝对指令吗？ | 是 | 不进 If-Then |

---

## 好规则 vs 坏规则

### 好规则

| 规则 | 为什么好 |
|------|----------|
| `feishu_create_doc` 创建后 → 提醒用户转移所有权 | 跨工具 + 固定流程 |
| 检测到同项目活跃会话 → 复用，禁止创建新代理 | 条件判断 + 防止冲突 |
| 用户要求"查原因" → 先读代码→定位问题→确认根因 | 操作序列明确 |

### 坏规则

| 规则 | 为什么坏 | 改进建议 |
|------|----------|----------|
| 使用飞书功能时 → 注意权限 | 过于笼统 | 拆分为具体操作 |
| 完成时 → 更新状态 | 无条件 | 加具体触发条件 |
| 重要文件 → 小心操作 | 主观判断 | 改为客观条件 |

---

## 格式要求

```
| 条件 | 行动 |
|------|------|
| 具体触发条件 | 具体动作（动词开头） |
```

| 要素 | 要求 |
|------|------|
| **条件** | 引号标注用户原话，或工具名 + 状态 |
| **行动** | 动词开头，主语省略，不加修饰语 |
| **粒度** | 一行一个动作，多动作用分号 |

---

## 常见错误

| 错误 | 示例 | 修正 |
|------|------|------|
| 条件模糊 | "用户说完成" | 改为具体触发条件 |
| 动作笼统 | "注意安全问题" | 改为具体操作 |
| 粒度过粗 | "项目完成 → 做很多事" | 拆分为多条规则 |
| 主观判断 | "觉得重要就..." | 改为客观标准 |
