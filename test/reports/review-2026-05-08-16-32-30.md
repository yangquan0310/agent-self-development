## 三、测试代码质量审查

### 🔴 [BLOCKER] `package.json` test 脚本在 Windows 上无法运行

**位置**：`package.json` 第 31 行  
**问题**：`"test": "node --test test/**/*.test.js"`  
在 Windows PowerShell / CMD 中，`**` glob 不会被 shell 展开，导致 `npm test` 执行失败：
```
Could not find '...\test\**\*.test.js'
```
**影响**：Windows 开发者无法通过 `npm test` 运行测试。  
**修复建议**：将脚本改为显式列出文件，或添加跨平台 glob 支持：
```json
"test": "node --test test/deviation-attribution.test.js test/heartbeat.test.js test/metacognition.test.js test/personality.test.js test/working-memory.test.js"
```

### 🟡 [WARNING] 多处 `async` 函数调用缺少 `await`

**位置**：
- `test/heartbeat.test.js` 第 13 行：`state.saveTask(k, v)` 在同步 `for...of` 循环中未 await
- `test/deviation-attribution.test.js` 第 30 行：`state.saveTask(...)` 未 await
- `test/metacognition.test.js` 第 14 行：`state.saveTask(k, v)` 未 await
- `test/personality.test.js` 第 13 行：`state.saveTask(k, v)` 未 await
- `test/working-memory.test.js` 第 14–15 行：`state.saveTask` / `state.saveSession` 未 await

**说明**：`createMockState` 的实现是同步的（`tasks.set`），所以当前不会导致失败。但如果 Mock 实现改为真正的异步（如 SQLite 适配器），这些测试会出现竞态条件。  
**修复建议**：在循环中添加 `await`，或改用 `Promise.all()`。

### 🟡 [WARNING] `working-memory.test.js` 中 "无 task 时跳过" 断言偏弱

**位置**：`test/working-memory.test.js` 第 57–62 行  
**问题**：
```javascript
const results = await api._emit('agent_end', {}, createMockCtx('r1'));
// 不抛异常即通过
assert.ok(results);
```
`results` 是一个空数组 `[]`，`assert.ok([])` 在 JavaScript 中永远为 `true`（数组是 truthy）。该测试只能捕获异常，无法验证无 task 时 handler 是否正确返回了 `undefined`。  
**修复建议**：改为 `assert.strictEqual(results[0], undefined)`。

---
